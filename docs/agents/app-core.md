Read this before changing the app's shell, its settings files, the dock, windows, Desktops, tiling, macOS's Dock, the menu bar, What's New, the settings window, the welcome, updates or the socket.

# Petal.app: the app, the dock and its windows

The rest of the app is in `app-ai.md`, `app-vault.md`, `app-computer-use.md`, `app-notes.md` and `app-settings-tools.md` (this folder).

## Petal.app

A native app in `macos/` (Swift Package Manager; `macos/build.sh` builds `macos/build/Petal.app`): the dock, its settings and AI, Petal AI's tools, the vault, routines and Petal Notes. Everything in `macos/Resources/` goes into the app as it is: the AI apps' marks (`claude.svg`, `openai.svg`), the Public Suffix List, the AI's tools (`mcp/tools.json`), the personal source's script (`personal/petal-personal`) and Petal's skill (`skill/SKILL.md`). `macos/Sources/Petal/`:

- `App.swift`: `PetalApp`, which everything shares: which dock is showing (Petal or macOS's), opening at login, launching, finding `claude`, the IPC functions, and quitting (`PetalApp.quit`, the one call to `terminate`: from the run loop, never inside a block of the main dispatch queue, because `applicationShouldTerminate` answers later and AppKit's wait for that answer inside such a block would stop the queue, the notes' drain and the answer itself; the answer comes back on the run loop too). `main.swift` starts it as a background app (no menu bar, no Dock icon), with a main menu that's never shown (`EditMenu.swift`: an empty app menu, and an Edit menu with Undo, Redo, Cut, Copy, Paste, Paste and Match Style, Delete, Select All and Find… on their standard selectors and keys), so the editing keys work in every text view; Petal's panels that take typing without activating Petal (notes, the chat) hand the menu their keys too (`EditMenu.keyEquivalent`). Escape on the note with the keyboard folds it and gives the keyboard back to the app the person was using (`NoteShelf.keyboardBack`), never by moving the pointer; the other open notes stay open.
- `Config.swift`: `settings.json` and `dock.json` in `~/.config/petal/` (the dock's apps are `dock.json`'s `apps`: `Config.apps`, `setApps`, `addApp`, `removeApp`, `importSystemDock`), read again within a second of any change (a file that's there but doesn't read as JSON keeps what was read before, an entry in `apps` that isn't text is passed over, and a number is taken as at most a million either way: `ConfigRules.swift`, its pure side) (`PETAL_CONFIG_DIR` points it at another folder, for benches and tests; `PETAL_SUPPORT_DIR` does the same for everything Petal keeps in Application Support, `Config.supportFolder`). A change Petal makes takes effect in memory at once and is written off the main thread, in order (`flush()` on quit). Each setting is watched on its own (`bool`, `string` and the rest): a change draws again only the views that show that setting; reading `settings` whole watches them all. Four settings say how far Petal AI may go without the person (`claudeAccess`, `computerUse`, `aiAllowed`, `aiNeverLook`), and they widen only through Settings, the chat's options or a card's Always: while Petal runs, a change in `settings.json` that would turn on Full access or using apps, allow more without asking or take an app off the private list isn't taken, and the file is written back to what Petal goes by (`ConfigRules.taken`, checked by `macos/checks/run.sh`); one that narrows any of them is taken, and at launch the file is read as it is. `Settings.swift` lists every setting once, with its default and help (see `app-settings-tools.md`). `ModesMigration.swift` (Foundation only; `Config.init` runs it before anything is read): a dock from when Petal had focus modes is kept, once: the default mode's apps are written to `dock.json` as `apps` and read back, and only then `modes.json` is removed (stopped anywhere, the next launch finishes it); the other modes are dropped and no copy is kept; a `modes.json` that can't be read is left alone and the dock starts empty, with Import macOS's Dock in its right-click menu; the settings that only meant something with modes, and six for looks nothing ever drew (`dockBorderColor`, `dockBorderOpacity`, `dockSheen`, `popupColor`, `popupOpacity`, `font`), leave `settings.json`, and the files only the removed features read are removed (`activity.jsonl`, `sorted.json`, `suggestions.json`, `writing-style.json`). `ModesLeftovers.swift`: what that needs the running app for, once: windows `parked.json` lists as put away for another mode go back to their frames (then the file goes; without Accessibility it waits), and a Do Not Disturb left on by held notifications (`quiet.json`) is turned off through the Shortcut that turned it on.
- `Dock.swift`: one Liquid Glass panel per screen (`DockController`, `DockPanel`, `DockView`): the AI button with its usage ring, a separator, the apps (the dock's own in their order, then the running ones that aren't among them; glow, badges, bounce, dots, launch pulse, drag to reorder, file drops), "+", now playing, minimized windows, stacks, the Trash, auto-hide. Clicking the app in front again brings its next window forward, through every one of them (`DockRules.swift`, its pure side). The panel is as long as the screen's edge and never resizes; the glass is centered in it and grows and shrinks around its centre. The panel runs to the screen's edge (the gap is inside it), and every slot's mouse fills its slot down to that edge, and along to the glass's end at the dock's ends. Whether the panel takes a click is decided from the glass as it's drawn now, its end slots followed frame by frame while it grows or shrinks, never from a size measured before; hover goes by the same rule (`DockPanel.takesMouse`). The glass is drawn behind the row, with no glass container, and the layer strip lays its icons out from the stage's centre, so an app coming or going moves the dock once, in one animation. Finder is its own button by the AI button (`FinderButton`, Petal's line mark for Finder on clear glass; `finderInDock`), never among the apps, so it never appears at the end and moves the rest. The note pad is the next one (`NotePadButton` in `NotePad.swift`, a small stack of paper in the default notebook's color on clear glass; `notesPad`, while `notes` is on): a click is ⌃⌥N, a drag takes a paper off it (`NoteDesk.dragPaper`), and it never moves or grows on hover. When the apps wouldn't fit along the edge, the icons shrink to fit (`ScreenDock.icon`, never under 16 pt), as macOS's Dock does. On a full-screen app's Space the dock keeps out of the way and comes out at the screen's edge, as with auto-hide. In Mission Control and App Exposé macOS's own Dock always comes out (no setting stops it), so Petal's steps aside until they close (`MissionControlWatch`, shared with Petal Notes and owned by neither). While Petal's dock is shown it keeps macOS's Dock hidden, so macOS's Dock on the screen is Mission Control bringing it out: whether it's really showing is watched ten times a second off the main thread (`DockProbe`: its one window asked about by id, under a tenth of a millisecond a look, and, only while that window is on the screen, where its bar sits through Accessibility, since a Dock that just started keeps an empty window up: `NoteShelf.dockBarShowing`), and that alone says open and closed (`NoteShelf.missionControl(dockOut:fullScreen:open:)`; in a full-screen app's Space the Dock coming out at the screen's edge says nothing). macOS 27 no longer sends the Dock's `AXExpose…` notifications, so this is the way that works there. With macOS's Dock chosen (notes on) its window is always on the screen and says nothing: there the `AXExpose…` notifications through `AXWatcher` say open and closed, on a macOS that sends them, with a check while it's open that the Dock still shows a window (`NoteShelf.missionControlOpen`), never longer than a minute past the last opening. Accessibility allowed in System Settings takes effect within a second for whoever listens to windows' events (`WindowEvents` polls it while anyone does, not on the dock's timer). Clicking the Trash opens it in Finder through Launch Services, never by telling Finder to activate (with "Click wallpaper to reveal desktop" on, that slid every window away). `DockStrip.swift`: the apps as Core Animation layers in one view ("+" is SwiftUI's glass over the slot the row keeps for it) (on by default; `defaults write tech.edgetr.petal layerStrip -bool NO` brings back the SwiftUI slots in `Dock.swift`). `Motion.swift`: the equalizer on Core Animation.
- `Popups.swift`: tooltips, window previews, stack popovers and Petal AI's question (`Popups.showAsk`: the Allow, Always, Don't card, when the chat asking isn't showing it) as glass panels over the dock. A glass panel hides by going clear and letting the mouse through, never by ordering out: taking a window with macOS's glass off the screen waits on the window server for up to half a second. The tooltip is AppKit's glass and a label, sized at once. Previews list an app's windows as the pointer arrives and swap straight to the next app's; none opens behind a menu. `Menus.swift`: every right-click menu, as macOS menus.
- `Windows.swift` (Accessibility: window lists, minimized windows, raising one window, the front window's title), `Spaces.swift` (which Desktop each screen shows, through SkyLight's private `SLSCopyManagedDisplaySpaces`, read-only, looked up at run time), `Signals.swift` (badges from macOS's hidden Dock, download progress through `NSProgress`, now playing from Music and Spotify: only a player the person allowed is asked anything, and one that hasn't been asked has "Show what's playing…" in its preview, so macOS never asks unannounced, and none is asked while Now playing is off; one playing shows before one paused; a badge going up bounces its app once, never every badge when Petal or macOS's Dock starts, and a read of the Dock that didn't answer changes nothing: `SignalRules.swift`, its pure side), `Stacks.swift`, `Apps.swift`, `Usage.swift` (the usage ring, every 5 minutes: Claude Code's login from the Keychain asks Anthropic's usage endpoint; `percent` is a 0–1 fraction).
- `Tiling.swift` (`tiling`: dwindle layout per Desktop, Control-Option keys, drag to swap), `WindowLayout.swift` (its pure maths, checked by `macos/checks/run.sh` without moving a window). Window ids come from the private `_AXUIElementGetWindow`, looked up at run time (and key `AppWindow`s, so a minimized window keeps its slot). A minimized window reports the subrole `AXDialog`, so it counts whatever its subrole says; `WindowEvents` in `Windows.swift` holds the Accessibility observers tiling, the notes and the dock share, on a thread of their own (`AXWatcher`), so a hung app never stalls the dock. The dock looks at the windows when one opens, closes, minimizes or stops moving (`LookSchedule.swift` decides when, checked by `macos/checks/run.sh`), with a look every 5 s as a safety net; without Accessibility it looks once a second.
- `SystemDock.swift`: hides macOS's Dock (auto-hide, 1000-second delay, and no bouncing: a hidden Dock still slides out to bounce an app asking for attention; Petal's own bounce comes from badges) (it keeps its edge, size and pace, so windows still minimize toward the bottom right, where Petal keeps them; in full screen macOS still shows it when the pointer pushes on its edge, which no setting stops, and slowing it left its labels stuck), only once the owner's own Dock settings are saved in `~/.config/petal/macos-dock.json`, and gives them back on quit, when killed, or on the next launch. The Dock guard (`~/Library/LaunchAgents/tech.edgetr.petal.guard.plist`, every 30 s) gives them back when Petal isn't running or has been deleted, and removes itself once Petal is gone. `petal restore-dock` does the same by hand. "Import Dock" reads the Dock's apps and folders.
- `State.swift` (`state.json` in Application Support: what Petal's own AI runs spent on an API key, when each stack was last opened, and the version Petal last ran as), `Hotkeys.swift` (Control-Option shortcuts through Carbon: the AI panel, the "+" search, a new note), `Magnify.swift` (magnification by transforms only, driven by a display link; its maths is `MagnifyRules.swift`, checked by `macos/checks/run.sh`; tooltips and previews sit past the grown icons), `MenuBar.swift` (the menu bar mark, blue with a dot while an update is ready; Petal Notes, settings, updates, and What's New in the Petal that's running, always), `SettingsExtras.swift` (the shortcuts card). Updates are announced in the menu bar, never with a dock card. **What's New opens by itself once after Petal starts as a newer version than it last ran as** (`state.json`'s `lastVersion`; `WhatsNew.swift`, pure, checked by `macos/checks/run.sh`; `ReleaseNotes.afterLaunch`): never on a first install, over the welcome or in a headless run, with each version missed since, newest first; it opens only once that version is kept (a `state.json` that can't be written opens nothing, a damaged one starts again, and a record that isn't plain numbers counts as none). The notes come with the app (`build.sh` copies `macos/notes/*.md` into `Resources/notes/`), so it needs no network; GitHub is asked only for a version the app doesn't carry (an update that waits). It is also in Settings › About.
- `SettingsWindow.swift`, `SettingsPages.swift`, `SettingsExtras.swift` and `Onboarding.swift`: the settings window and the first-run welcome. **Settings is one glass layer:** the window's own Liquid Glass and nothing else of glass but its controls. Across its top, the ask bar: typing shows the settings that match, from every page, as their real rows; Return opens the first setting found, and hands the words to Petal AI only when nothing matched (with no AI chosen it only searches); a row is found by its own words and by its page's name beside them. Down its side, a row a page with a flat tile in its part's color (`Part`) and a dot by the page showing: Dock, Look, Notes, Petal AI, Vault, Routines, Privacy, About (`SettingsSection`; `claude`, `apps` and `permissions` still open Petal AI, Dock and Privacy, and `petal settings <page>` opens one by name). A page is its title, then groups: a small label, rows with hairlines between, space before the next. Every row is one `SettingsEntry` in `SettingsList` (`SettingsPages.swift`), with the words it's found by, used by its page and by the search: a new setting's row is one entry there. Switches sit in one column at the right edge in their page's color, sliders start on one line, and a row has a line under its name only where its switch is risky or its name can't say it. Look keeps the dock itself in view above its rows (`DockView`, with the person's apps), following each change as it's made. Notes picks the notes' look from two real papers. Privacy holds the apps kept private, what Petal AI did, memory, what's allowed without asking, and what macOS lets Petal see. **The welcome** is Petal's four parts on their four colors (Notes, Petal AI, A vault, A dock), then what must be decided now: bringing the Dock along, which AI, windows (Accessibility, the one permission asked here, because the dock needs it at once) and opening at login; each AI's row says what it is ("Petal AI, with Claude") and that it uses the person's own plan; Screen Recording, browsers' tabs and what's playing are each asked where they're first used. An Allow… pressed again opens that permission's list in System Settings (`Windows.askForPermission`, `Capture.askForPermission`). The settings window is made ahead while it's closed (`SettingsWindow.makeAhead`, a while after launch and a moment after each close, never with anything from the last opening), so opening it only shows it; what its pages show of macOS and of files (the login item, macOS's Dock, Desktops, Codex's model, the notes for the AI) is read off the main thread (`PetalApp.refreshSystemFacts`), never while they draw. A closed welcome or What's New window lets its views go, so their timers stop. A chat's messages are lazy and its markdown is parsed once per text (`ParsedMarkdown`). The vault's rows in Settings stay eager: a lazy list on a settings page sets AppKit's constraint updates looping as the page comes in (the window stops updating, or AppKit throws). `Setup.swift`: getting Claude ready (installs Claude Code with Anthropic's installer when it's missing, and runs `claude auth login`, which finishes in the browser), and the Dock guard. `MCP.swift`: Petal's tools for the AI (`Petal --mcp`). `Updater.swift`: updates from `macos-v*` releases (with `autoUpdate` off, a check the person asks for stops at "available", with What's new and Install, and downloads nothing until Install; turning `autoUpdate` on checks at once), installed only when the download matches its release's checksum, is signed, whole, with Petal's own certificate and is the very version its release names, newer than the one running (a release's version is read only when it is plain numbers) (`UpdateTrust.swift`: the certificate by its hash, whatever signed the Petal that's running; `petal personal reset` goes by the same rule), and looked at again once it's in place (`UpdateTrust.install`: an update that isn't the one checked there is said, never offered for a restart). `IPC.swift`: the socket. `Snapshot.swift`: `--snapshot`.

How the pieces fit:

- **One dock,** the same on every Desktop: the apps in `dock.json`'s `apps`, then the running apps that aren't among them (every running app, hidden or with no window too, with a dot that is fainter when it has no window here; `thisWorkspaceOnly` leaves out only one whose windows are all on another Desktop: `DockRules.shows`). An app dragged off the dock is removed (a running app that isn't kept, let go outside, stays as it was), and an app, a folder or a web address dropped on it is added (`DockDrops.swift`, `DockRules.drop`, `dragEnd`, which decides from where the pointer is, never from how the icon looks). A drag over the dock is weighed from its addresses alone; the disk is read off the main thread, on the drop. The AI button shows whenever an AI is chosen. The dock doesn't show over full-screen apps.
- **Which dock:** the first launch offers to import macOS's Dock (its apps become Petal's, in its order; its folders become stacks), then hides macOS's Dock. Import macOS's Dock in Settings, into a dock that has apps, only adds: the apps and folders Petal's dock doesn't have yet go after its own (`DockImport.merge`, pure and checked: it replaces only into an empty dock on the very first setup, and never the person's own stacks afterwards). Closing the welcome is Keep macOS's Dock. Choosing macOS's Dock in the settings window (or the right-click menu) turns Petal's dock off; opening Petal again opens its settings.
- **`dock.json`** holds the dock's apps (`apps`: bundle identifiers and `https://` addresses, in the order they show), where it sits (`position`: bottom, left or right; `autoHide`) and the person's other choices (`dock`: petal or macos; `keepWindowsClear`; `openAtLogin`; `welcomed`).
- **Room for the dock:** macOS reserves space only for its own Dock. With `keepWindowsClear` on and auto-hide off, Petal shortens (or, for a side dock, narrows) any window reaching into the dock's strip through Accessibility, to end where the dock's glass begins, and moves out one too small to shorten; a window the person moved there at its own size is moved back out instead of shortened. Each frame is asked for once: a window whose app keeps it bigger than asked is moved out at the size it kept, and one dragged in at its size stays moved out (`DockRules.clear`, `ClearLedger`, checked over generated runs by `macos/checks/run.sh`). Petal remembers each window's frame from before it touched it: a new position starts from that frame (windows never shrink step by step), and turning it off, auto-hide or full screen gives it back. A window the person moved since is theirs.
- **IPC:** the socket `~/.config/petal/petal.sock`: write one JSON array (`["dock", "macos"]`), read one line. A request that asks the person (`assist`, `agentKeys`) sends a space every 10 s ahead of its line while its card is up, and closing the socket before the answer ends it: what it had going stops and its card is answered Don't. `petal` and `Petal --mcp` use it. Words sent to `chat` are typed into the chat for the person to send, never sent as theirs. The functions it answers are listed in `macos/checks/run.sh`; a new one is added there on purpose.
- **The AI's tools** are Petal itself, `Petal --mcp`, given to Claude with `--mcp-config` and to Codex with `-c mcp_servers.petal…` (approved ahead, since `codex exec` can't ask), so nothing needs installing. Each tool's name, description and input schema is in `macos/Resources/mcp/tools.json`, served as it is; `MCP.swift` does what each tool does. `petal_get_state` reports the settings (with their help) and the dock's apps, and `petal_set_dock` changes them (`add`, `remove`, or `apps` for the whole list in its order).
- **AI is optional.** `aiProviders` lists the AIs the person chose (`claude`, `codex`, both, or `[]` for none: the dock works whole without AI); `chatProvider` is the one the chat, usage ring and sorting use. The welcome window starts with whichever are already installed switched on. For each one chosen, the welcome and settings windows install it with its maker's own installer and run its sign-in (`claude auth login`, `codex login`), which finishes in the browser. Nobody types a command.
- **An API key instead of a subscription** (`claudeAuth`, `codexAuth`: `subscription` or `api`): the CLIs stay the runtime. The key is pasted in Settings › Petal AI and kept in the Keychain (service `tech.edgetr.petal.api`, account `anthropic` or `openai`), never in a file. Only the processes Petal starts get it, in their environment: `ANTHROPIC_API_KEY` (which beats a claude.ai login in `-p` runs) with `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`, so the commands and MCP servers Claude starts don't see it; `CODEX_API_KEY` (which `codex exec` uses over `~/.codex/auth.json`) with `shell_environment_policy.ignore_default_excludes=false`. Petal never changes `~/.claude`, `~/.claude.json`, `~/.codex` or Claude Code's Keychain item: the person's own Claude Code and Codex keep their sign-in. With `api` and no key saved, nothing runs (never a quiet fall back to the subscription); a refused key says so in the chat with a button to Settings › Petal AI.
- **Usage ring:** Claude's from the usage endpoint; Codex's from the rate limits in its newest session log (`~/.codex/sessions`). On an API key there are no limits: the ring stays empty, and the panel's header, the tooltip and Settings › Petal AI show what Petal's own runs spent this month (`aiSpend` in `state.json`): Claude Code's `total_cost_usd`, and Codex's tokens at approximate list prices (`APIPricing`).
- **Settings window:** everything Petal can change, on one layer of Liquid Glass over whatever is behind it; the bar across its top searches the settings and asks Petal AI. The right-click menu stays tiny.
- **Quick actions:** macOS doesn't let other apps read an app's own Dock menu, so an app's right-click menu lists its windows and the item ⌘N is in that app, by the app's own name for it ("New Message"; left out when it has none), with Open for an app that isn't running, Hide, Minimize All and Quit (Force Quit while Option is held). Finder's own menu has no Quit.
