Read this before saying a change works, and before adding or changing a check, a bench or a snapshot.

# Verification

- **Build and run:** `macos/build.sh`, then run `macos/build/Petal.app/Contents/MacOS/Petal` (`PETAL_KEEP_DOCK=1` leaves macOS's Dock alone). `printf '["version"]\n' | nc -U ~/.config/petal/petal.sock` talks to it. After quitting, `defaults read com.apple.dock autohide` shows the owner's Dock setting is back.
- **Speed:** `Petal --bench` times the work behind the dock (listing apps, a search, the window list, Accessibility) without showing anything; `Petal --bench-dock [folder]` lays out and draws the dock off screen with the person's own apps (an empty dock: the first installed ones), with the SwiftUI slots and with the layer strip (and writes the strip as a PNG into `folder`), then drives the real dock's magnifier with a made-up pointer (`DockMagnifyCheck.swift`: both drawing paths, every position, switched on from the start and while the dock shows) and exits non-zero when an icon doesn't grow, leaves the pointer, overlaps a neighbour or never settles; `petal bench` runs the same code a click does inside the running Petal (bringing apps forward, the dock's update with both strips, the "+" search, the dock's refresh) for about 15 seconds and writes `~/Library/Logs/Petal/bench.json`, with each step's time from `Perf.span`; `petal bench quiet` runs only the steps that leave the apps alone (sweeping across the icons, a setting back and forth). `Petal --bench-windows [--runs N] [--json file] [--png folder] [--only name]` times every other window and panel the same headless way (`--bench-settings` only the settings window): opening (first in a fresh process, and again), switching pages, typing, a switch, a slider, scrolling top to bottom in 8 pt steps (per step: median, p95, p99, steps over 8.3 and 16.7 ms, jitter), each window's idle CPU alone in a fresh process, and what Petal uses in the background once they're closed. It never shows anything, opens no socket, reads no Keychain, starts no AI app and saves no chat (`Headless`), uses a made-up vault, and works on a copy of the settings in a temporary folder (`PETAL_CONFIG_DIR`) and an empty one for Petal's state (`PETAL_SUPPORT_DIR`), so it never reads or writes the person's; `pngdiff.py` fails on an image missing from either folder; `--png` writes what each window drew (its layers: a glass container draws white there, so glass windows are checked with `--snapshot`). `Petal --bench-notes [--json file]` times Petal Notes with 500 made-up notes in 20 notebooks the same headless way (the first read, a read after one change, the Petal Notes window, a search typed a character at a time, the tools' search, the grid scrolled, edge tabs, a note with 20 pictures, idle CPU), on folders of its own whatever the environment says, with the longest the main thread was held beside each time. `macos/bench/` holds the before and after results (`notes-before-after.txt` for notes) and `pngdiff.py`, which compares two folders of PNGs. Compare before and after a change; never on the owner's screen while they're working without saying so. The dock's main thread must never wait on the window server, Launch Services, AppleScript or the disk: those run off it.
- **Without touching the screen:** `Petal --snapshot <folder>` draws every view (dock, each settings page whole `settings-dock`, `-look`, `-notes`, `-ai`, `-vault`, `-routines`, `-privacy`, `-about` and a search in them `settings-search`, welcome, the chat's panel, the "+" search `search` and with results `search-results`, a player's preview that asks first `preview-player-ask`, Petal AI's question cards, stacks, the switch for a display per run `settings-run-displays`, the AI button's preview with runs on displays of their own `preview-notes-displays` (a display from a made-up picture with Show me, a run waiting for a display, an outside session's tile), and Petal Notes: `note-folded`, `note-open`, an empty one `note-empty`, three papers on one window `note-beside`, papers in two columns with one opened `note-columns`, `note-back`, `note-glass`, `note-sentence`, `note-edge-tabs`, `note-on-screen`, the note pad with a paper coming off it `dock-note-pad`, `quick-question`, the Petal Notes window `notes-window-grid` (and `-dark`), `notes-window-canvas`, `notes-window-private`, a notebook's stack and fan `dock-notebook-stack`, a note on a person beside a chat `note-person`, the window at its smallest with 25 notebooks `notes-window-many` (the list scrolling, "+ Notebook" pinned under it), and helpers in notes: `helper-at-menu`, `helper-ink`, `helper-back`, `helper-working`, `helper-watcher`, `helper-task`, `helper-code`, `quick-question-sources`, and the viewer: `viewer-pdf`, `viewer-slides`, `viewer-versions`, from made-up notes and documents) into PNGs. `Petal --viewer-check [<file>…] [--out <folder>]` loads files as the viewer does without showing anything (a PDF read, a deck's or document's pages through Quick Look, or Quick Look's own view); given no file it makes its own in a throwaway folder (`ViewerSamples`: a PDF, a Word document and a deck), so with no arguments it just runs. It writes a PDF's made-up notes as comments into a copy beside it (and removes it), then on throwaway copies of its own: comment writes refused on a changed PDF and a hung-up asker, a dropped Quick Look export cleaned up, a preview with a remote picture loading nothing (a local server counts the requests; without the rule list it sees one), and an off-screen viewer window (the selection, a passage found by its words whatever coordinates it was saved with, a moved one, the margin and pages scrolling in step): given files, they must be throwaway ones you made in a temporary folder. It points `PETAL_CONFIG_DIR`, `PETAL_SUPPORT_DIR` and `PETAL_NOTES` at folders of its own wherever the run doesn't set them (never the person's, never a copy of theirs). Native controls and scroll views draw as placeholders there; check those live. Don't test on the owner's screen while they're in a call or sharing it.
- **Helpers in notes, end to end:** `Petal --helpers-check [--ai]` runs helpers for real without showing anything (`HelpersCheck.swift`): headless, on throwaway folders it makes itself, a made-up vault, no socket, never the Keychain. It builds the real `PetalApp`, gives each note its real editor, types a line and presses Return; the AI app is a stand-in the check writes there that plays a fixed transcript, and everything on Petal's side of that process is the real path. One line per step (19 of them: a plain line, a secret redacted, Stop, a failure, a follow-up, recalculate and put away, a watcher, a second opinion, notes not ready, a Private source, the private apps changing, a note in the viewer's margin, Allow with every place taken, the reading lens, a hidden display for each run with made-up displays, what a run leaves on its display however it ends, two runs taking turns on an app, those last two with made-up apps and windows as well, a chain and a watcher that are only in a note's file starting nothing while typed ones work, and `settings.json` changed outside Petal while it runs), non-zero on any failure. `--ai` runs three of them once more with the person's own Claude Code (Haiku at low effort) or Codex, a handful of short calls. What each step shows, and what it can't drive (the paper's own panel, the 30-second clock, real windows, coding helpers' worktrees), is in `docs/petal-notes.md`.
- **Routines:** `Petal --routines-check` runs routines on throwaway folders in the temporary folder (`--ai` sorts with Claude Haiku: a few quick calls), and checks that a link in a tidied folder is never followed or moved, that a routine that opens something or runs a Shortcut asks before it's saved, changed or run by hand (the check answers the card; nothing is opened or run), that routines saved when the Mac had modes are listed, never run and written back as they were, and that one written by hand with a folder outside the home folder never runs; never point a test at the owner's real Downloads.
- **A note's editor never drops a refused save:** when `write` can't land (the notes' folder switching, a drain, the paper gone) the typing goes into the journal at once as a whole snapshot under its note's id, the editor stays dirty, takes no newer version meanwhile and tries again until it lands (`NoteStore.journalUnsaved`, `EditorMarker.saved(landed:)`; the whole rule is in `docs/petal-notes.md`).
- **A hidden display, live:** `Petal --display-check <folder>` is the one thing that makes a real display outside a run: one display, placed at a corner, a throwaway text file opened in TextEdit without activating it, its window moved onto the display and its text set through Accessibility alone (no AppleScript, no System Events), a PNG of the display written into the folder, the app and window in front and the person's screens shown unchanged, then the window closed and the display removed (gone from macOS's list of online displays); one line per step, "ok" or "FAIL" with what was read, the exit code the number of failures. Indented lines are what it read, never a verdict: each place asked for with what macOS answered to each of the three calls and from which thread, the shared edge with each of the person's screens, how long making, placing and removing took, and what AppKit and `CGDisplayIsOnline` say. `Petal --display-check <folder> --full` goes through all of it for about a minute with the controller Petal itself uses (`RunDisplays`, on its own), TextEdit and Calculator, throwaway files, and Accessibility alone: two runs get a display each at two different corners, out of the pointer's reach, and the person's screens don't move; with the limit at 2 a third waits and gets one when one is freed; a second run asking for the app the first is using waits and gets it when the first ends; each run's window is on its own display and not listed for the other; Show me brings a run's window to the main screen while its display stays; an app a run started is quit when the run ends, and one that was open before is left running; at the end no display, no app and no window of the check's is left. When the app in front changed, it prints which app came forward: a FAIL only when the check started it. Either one rearranges the screens for a while: only the owner, or the main session with a heads-up, runs it; an agent working alone never does, and no check, bench or snapshot ever makes a display (a headless run has no maker; `--helpers-check` uses made-up ones).
- **A run's browser:** `Petal --browser-check` drives a run's browser for real without showing anything (`BrowserCheck.swift`): headless, on throwaway folders it makes itself, a made-up vault and a made-up display (it never creates one), no socket. The browser is Playwright's headless shell from the person's caches (no window at all), started exactly as a run's is; the pages come from a small server the check starts on this Mac (127.0.0.1 and localhost, two sites) and one made-up https shop the browser answers for itself, so nothing leaves the Mac. Everything goes through the real tools and the real cards: 23 steps (asked once, then a browser over the pipe; read with ids and no secrets; click; type, select, check; key and wait; tabs, a page's message, a download refused; a login filled on its own site and the site getting it; refused on another site, in another site's frame and on http; a card only after Buy and only on that page; a new login made and saved, and one the person types into Petal's card; What only the live run shows: that a browser started this way never comes to the front and its window stays on the run's display, Show me, the person opening their own copy of that browser meanwhile, and a real browser's own clipboard (the headless shell keeps one of its own, so the check stands in for a page's copy).
