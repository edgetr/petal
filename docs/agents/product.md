# Petal: the product

## Project

Petal is an AI-native dock for the Mac, with Claude built in: a native app (macOS 26 and later, in `macos/`) that replaces macOS's Dock with one dock of the person's apps, and has Petal AI, the vault, routines and Petal Notes. It runs on the Mac only.

- **One dock:** Petal's dock is one list of apps and website shortcuts, in the order they show, the same on every Desktop (`dock.json`'s `apps`), in Petal's accent. It has a built-in tiling window manager (`tiling`, off by default), per Desktop.
- **Website shortcuts:** an `https://` address among the dock's apps is a dock item with the site's own icon and a globe badge. A mail address or another kind of link (`mailto:`) is never taken for a website.
- **AI in the dock, optional:** the AI button opens a chat with the user's own Claude Code or Codex (their own CLI and plan; `aiProviders` picks Claude, Codex, both or none, and `chatProvider` the one the chat uses). Petal's tools let it change any setting and the dock's apps; when a setting can't do it, it may edit Petal's code. A ring around the button shows that AI's usage.
- **Petal AI, a helper on the Mac:** through Petal's tools it sees what's in front (app, window, the browser tab's address, selected text, a screenshot when asked), opens, quits and arranges apps and windows (what it opens besides an app is a web address, a document or a folder, never a script, a program or another app's own kind of link), moves files to the Trash (never deletes), and logs in, fills forms and checks out with the person's vault without seeing a password, card or key (`petal_vault`); the person's own agents in T3 Code or a terminal use the vault the same way, and run commands with an API key they never see (`petal run`), once the person allows them per project. What changes things asks first with a card (Allow, Always, Don't) unless the chat has Full access; Full access and Always cover Petal's own chats and helpers and the person's own Claude Code and Codex (signed by their makers), whose cards say who asks; any other program is asked every time, with no Always. It remembers what helps (`aiMemory`), takes files dropped on its button, uses the person's apps for them (`computerUse`: it reads a window's controls and presses, types and chooses menus through Accessibility, with a pointer of its own (pink, or the person's `pointerColor`), asking before each app; the person's pointer never moves, and Stop or Escape ends it), runs routines the person describes in their own words (`routines`: "keep my Downloads tidy", "when I open Xcode, hide Messages"), and fixes Petal for the person (doctor, logs, settings, the personal source) without asking them to type anything. The AI button opens the quick question: a chat stuck nowhere, always over the dock in its one place (its panel can't be dragged); while it answers with the panel closed the button's mark fades in and out, and an answer not seen yet shows ✦; Stick here makes it a Petal Note on what was in front. The machinery that let a chat work in its own window in the background (no pointer, nothing comes forward) and show at work when the AI button is hovered is what helpers in notes use.
- **Petal Notes** (`notes`): the person's own writing on paper, stuck to places: a sentence (the quote, the words around it, and its page or file), a browser tab, a window, all of an app, a file in any app, a Desktop, or the screen itself ("On screen": it shows at its spot on every Desktop, whatever is in front, on this Mac only); one note can be on several. On a window, notes rest as tabs on its right edge at the height of their line (or stacked at the top); clicking one shows the note beside the window, open to write in (headings, checkboxes, links that become cards, pasted or dropped pictures; a click on a link opens only a web or mail address, or a document on the Mac, anything else of a file shown in Finder), and clicking away folds it to a 170-point square; Put away (the letterhead's menu, or Escape on the folded paper) hides it until its tab or the Petal Notes window brings it back. Petal narrows a window with no room beside it when a note on it opens, keeps that room while any of its papers shows there, folded or open, and gives the width back when none does, so a window is resized once. Papers beside a window never cover one another (`NoteRoom.stack`): one the person moved stays where they left it and the others go around it, a new one takes free room and moves nobody, the ones below a paper that grows move down with it, and with no room below they go on in another column; a paper nobody touched keeps its exact place when another opens or grows. A request sent with Return leaves the writing as a bubble that shows it working (its step, Pause and Stop), and its answer sits right under it; one that didn't finish offers Try again (only for a request this Mac sent) and Edit; a request added at the end of a line takes only its own words, and the line's start stays. A paper is picked up from anywhere on it that isn't a control or the writing being edited (the pointer is an open hand there) and stays exactly where it's let go, over its window or anywhere else, by its window's nearest corner; one the person put somewhere never narrows its window or goes back beside it. Notes neither changed nor opened for 30 days fade to a line. An empty note says "Write, or type @ to ask Petal AI"; one still empty goes to the Trash when it's put away or its window or tab is left, never on a click elsewhere. Paper (`notesLook`: paper, or Liquid Glass) in its notebook's color; the letterhead says where it's stuck and its notebook, and changes either; the folded corner turns it over. Each note is a Markdown file, each notebook a folder (Inbox by default, its color on its cover), in iCloud Drive. Made with the note pad in the dock (`notesPad`: a click for a note on what's in front, or a paper dragged off it and let go anywhere: on the window under it at that spot, else on that Desktop, or holding Option on the screen itself), ⌃⌥N, "Note" by selected text, a drag out of the AI button, or Stick here; with a window of Petal's own in front, the pad, ⌃⌥N and "+ Note" in the Petal Notes window make one on the Desktop showing, open near the middle of the screen, an ordinary Desktop note. A note can also be on a person: it shows beside their conversation in Messages, WhatsApp, Telegram, Slack or Mail. The Petal Notes window (the menu bar's mark) holds every note: search, Coming back, Watching and Helpers at work, and each notebook (its cover first, then its notes as a grid, or laid out freely on a canvas with areas, arrows and words). A notebook can be Private (its notes kept from Petal AI and the note tools unless asked from inside it, from the AI button's previews and other notebooks' memory, and out of Petal's own pictures; not a protection from other apps' screen recordings) and kept in the dock as a stack whose papers fan up; dropping a note on an app in the dock uses it there (Mail: a draft; Calendar: an event, asked first; any other app: its words on the clipboard), never sending anything. AI comes in only when called with @ (helpers in notes, below); Petal AI and the person's agents read and write notes with the note tools. **Petal's viewer** (Petal Notes' fourth phase) shows a document in a window of Petal's own with the notes on that file in a real margin: a PDF through PDFKit with exact passages (select, then Note), Word, PowerPoint, Keynote, Excel and the rest through macOS's own Quick Look preview with notes per page or slide, never an Office engine of Petal's; Open in <app> is one click away. It reloads when the file changes ("Updated just now") and never moves or changes it; versions of a change are tried on copies first. A note in its margin can follow what the person selects (its menu: Follow what I select): each selection that settles is handed to the quick AI with what the note says to do (an empty note: explain it in plain words), and the short answer shows beside the paragraph.
- **Helpers in notes:** typing @ in a note shows a small menu (Petal, then notes and notebooks by name); each @ and each word it understood (this page, this sentence, Friday, a model's name) shows a chip of what it bound to. A helper runs only when the person presses Return at the end of that line in that note, and only when the line as it is now was written or edited by the person: a paste in the editor is the person's own edit, but imported, synced or tool-written text never runs anything, and after a restart, or with its editor closed, an old line runs again only once it's edited. @Petal runs the person's chat AI with Petal's tools on the note's place (in the background; four at once at most), the notebook's cover read first; its answer is one block of ink on the front (the next replaces it), its steps and a stamp for each thing allowed on the back (tapping a stamp takes the grant back). Allow, Don't and Buy cards show on the note; Stop and Pause are its only buttons, everything else is said in words: "bring this back Friday" (a day, a time alone, "the 20th", a month and day, "next month"; an hour said with the evening or tonight is the evening's, and a time today that has already gone by is never taken; with no time Petal asks when), "remember …" / "forget …" (the cover's "Petal remembers" lines), "put this away" (the window's tabs, file and mail into the note, with Open all, which never launches an app or a script), "check this every morning, tell me under $300" (a watcher on one Mac that fetches plainly and asks the AI only when it can't read the value or the line is crossed; never buys), "make this recalculate", "when @Research is done, draft @Proposal", "check this against @Notebook", "leave me a note every morning". Only a plain instruction takes one of those routes; a question, a condition or a negation goes to the helper as an ordinary request. A chain, a watcher or a morning note goes on only on the Mac where the person's own line set it up (kept in that Mac's own notes state, never synced): one that is only in a note's file, or whose words were changed there, does nothing. A note on a GitHub pull request or issue, or on a file in a git repository in the home folder, runs the person's own Claude Code or Codex in the note's own git worktree of that checkout (asked once per project on the note; on a pull request from a fork, and for a second opinion, what the code brings along for an AI isn't loaded: for Claude Code the project's settings and their hooks, its tool servers and its instructions, for Codex its instructions), but only when its line asks for work or the note has its worktree already: a question there is answered like any other, and so is one where no checkout is found, or a line about the note itself ("fix the typo in this note"); with the PR link and proof as ink; "have GPT 6.1 Sol look for holes" adds a second opinion. Models are named in words; there are no @Claude or @Codex entries. A Private notebook is read only by a note inside it, and its helpers never show in the AI button's previews. Everything a helper says is put through the vault's redaction before it's shown or kept. What makes a line runnable, how every run starts, is admitted and ends, and what each route does exactly are in `docs/petal-notes.md`.
- **A display of its own for each run** (`runDisplays`, on by default; Settings › Petal AI): a Petal AI run opens its windows on a hidden display made for it, which the person doesn't see and their pointer can't reach, so its work never shows up in front of them. A run is a helper in a note with everything that note starts (a second opinion shares its display), a chat's reply, or an AI session outside Petal; it gets a display the first time it opens something with `petal_apps`, never before, and past the limit (one per 8 GB of memory, at least 1, at most 4; `runDisplaysLimit` lowers it) it waits its turn ("Waiting for a display"). A helper and an outside session open there unless they say the person's screen (`on: "screen"`); the quick question opens on the person's screen unless it says `on: "display"`. Only a window that open made is ever moved there, through Accessibility, with nothing activated or brought forward: an address in a browser the person already has open (it would be a tab in their window), or an app they already have open asked for by itself, opens nothing and says so. On its display a run works the background way always (no pointer); its questions, Buy cards and the vault's card stay over the dock or on the note, on the person's screen. The AI button's preview shows each run's display, live, with Stop and Show me, which brings its windows to the person's screen while it goes on. The display goes when the run ends, however it ends, and what the run left is put away first. An app the run itself started (it wasn't running before), which the person hasn't used since and which has nothing unsaved, is asked to quit, politely, never forced; an app the person already had open is never quit, and one the person used (they switched to it, typed or clicked in it, or took a window of it with Show me) is theirs from then on. Where Petal can't tell whether anything is unsaved, or the app doesn't quit within a few seconds (it asked to save, say), it's kept. Of the windows left then, one the run opened and left empty, or a dialog with no document behind it (an Open panel, a welcome window), is closed; anything else is brought back to the person's main screen, never lost. Two runs take turns on one app: a run that asks to open something in, or act in, an app another run is using on its display waits in order ("Waiting for TextEdit", where "Waiting for a display" shows) and gets it when that run ends or lets it go, and a run never sees or touches another run's windows. The person's own use of an app wins: a run that needs real keys in an app they're using waits for them to leave it, and says so the same way; what they ask the quick question to do in an app never waits behind a helper.
- **A browser of its own for each run** (`petal_browser`, with `runDisplays` on): a run that works on the web gets a browser of its own, so the person's browser is never shared with it and several runs never meet. It is a separate copy of a Chromium-family browser the person already has (Google Chrome, Microsoft Edge, Brave, Vivaldi or Helium, signed by its maker; `runBrowser` names one, else Petal takes one they don't have open; never the one their links open in, named or not, since macOS would open their links in the run's copy; Petal installs none, and says so when there is none or only theirs), started by Petal as its own child, never through Launch Services, with a fresh profile under Petal's own folder (signed in to nothing, no extensions, no sync, no sound), its window on the run's display from the start. Petal drives it through the browser's own remote control over a pipe (no port is opened, so nothing else on the Mac can drive it): no pointer, no keyboard, nothing in front, so the person's typing can't land in a run's page, nor a run's in theirs. One tool with actions: open an address (https, or http on this Mac), read the page as text with an id on everything that can be used (never a password field's value; everything through the vault's redaction, nothing while the vault can't be read), click, type, select, check, key, scroll, wait, tabs, back, forward and reload. The first use in a reply asks the person once (Allow covers the reply), on the note or over the dock; Stop, Pause, a new turn or the setting turned off end it before its next change. It never types into a password, card or token field: the vault fills those there too, without anything coming forward, by its own rules unchanged, from what the browser itself says of the page (the frame a field is in and whose that document is, the tab's page, the browser's own record of the tab). Whose a document is comes from the browser, never from its address: a page the browser keeps apart from its site (a sandboxed document or frame) is never that site, so a login there asks first and payment info never goes in, and a frame with no address of its own is the site's that made it. A fill stays with the very field it was planned for: one the page replaced, or that was read again while a card waited, gets nothing. Where a tab got to by itself (a link, a redirect, a page's script) is asked again before a page is read or a key goes to it: only an address open would take is read and worked in, never the browser's own pages (a certificate warning is never pressed through), a file, or a page that isn't https anywhere but on this Mac (`RunBrowserRules.landed`). Its window's own controls (the address bar, its menus) are never used: `petal_ui` and `petal_act` refuse a run's browser. Nothing is downloaded (a download is refused and said) and no file can be chosen; a page's own message is closed and told. No page writes or reads the person's clipboard by itself (the browser is told to refuse it for every site); a page can still copy on a press, so the clipboard is watched for a few seconds after each one, and what the press itself copied is cleared and said, never a copy the person may have made. There are no pictures of a page yet. It ends with its run, however the run ends, and its profile is removed with it; a Petal that crashes leaves none (the pipe closing ends the browser, and the next launch ends and removes whatever is left). Petal's dock, window lists, previews, routines and tools never take a run's browser for one of the person's apps. When the person means the page they're looking at, that is still `petal_look` and `petal_ui` on their own window.
- **A good dock:** badges, bounce, download progress, quick actions and recent files, drops, window previews, minimized windows, now playing, folder stacks, auto-hide, one dock per screen.
- **Settings:** the right-click menu stays tiny (position and auto-hide). Everything else is in the settings window, or changed by asking the AI.

- **Status:** released, at 2.1.x (`macos/VERSION`); it updates itself from GitHub Releases.
- **Business model:** free and open source. Petal has no server and no analytics. Its AI features use the user's own Claude Code or Codex login, and count toward that plan's usage, or the user's own Anthropic or OpenAI API key. Without an AI app, everything else works.
- **Wording:** Petal is a Mac app: say the Mac for where it runs, and macOS 26 or later for what it needs.
