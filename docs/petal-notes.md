Updated 2026-11-10. `AGENTS.md` says what Petal Notes is and the rules every agent must always follow. This file holds the rest: how each part works, rule by rule, as it was settled while phases 1 to 5 were built and reviewed. It states what holds now, not its history. Read the part you're about to change before you change it; a review will hold you to it.

## Helpers in notes, as the person meets them

### What the person sees, and what a line may run

**Helpers in notes**: typing @ in a note shows a small menu (Petal, then notes and notebooks by name); each @ and each word it understood (this page, this sentence, Friday, a model's name) shows a chip of what it bound to. A helper runs only when the person presses Return at the end of that line in that note, and only when the line as it is now was written or edited by the person: the editor knows each line by its identity there, a mark on its characters (`NoteLine`, in memory only; nothing about a line's words is kept), never by its text. Only the person's own typing or pasting gives a new mark that may run, and only to the lines its characters land on (deleting, a line break too, never marks: Backspace joining a blank line onto an answered line doesn't make it runnable); every change takes the mark off the lines it touches, undo, redo and autocorrect the line before them too, text set through Accessibility (another program writing into the editor: its value, or the text at its selection) counts as text from outside and never marks, and text from a sync, a reload or a tool clears them all (`NoteHelp.editedLines`, `NoteTextView.remark`, `fromOutside`, `replaceFromOutside`); only the person's own Return at the very end of a line touches nothing.

Return on a line that can't run (answered before, loaded from disk or a sync, brought back by undo) only makes a new line; running it marks it ran; a run that fails or is stopped, a local refusal, and a follow-up that never ran (its line goes with it through delivery and is held by the run until that turn succeeds) make that very line runnable again, while its editor is open and the line is as it was (a second opinion asked while a helper works rides in the same queue as follow-ups, with its line: given back if that run doesn't succeed, held by the reviewer's run until it does). Every run kind (a chat helper, a coding one, a second opinion, a quick one: recalculate or put away, and a watcher's look, a run of its own never in `runs`) ends through one function, `NoteHelpers.end`, once per token (an end for a run already ended returns at once): its token completes, it's let go, everything it produced lands as one result (`NoteHelp.Result`: its ink, a second opinion's own opinion, its steps, a recalculation's `calc`, a task put away and the helper line, as one journal entry and one based write, or not at all), `helper: done` only on success (what chains and morning notes wait for), `failed` with its reason, cleared when stopped (a look never writes ink or the helper line), and its lines are passed on (success hands on what was asked of it, a second opinion with that one's line; a failure or stop gives its line back).

Right before a result lands, on the main actor, the admission gate is asked again from what's true then (`NoteHelpers.landing`: a source that moved into a Private notebook while the AI worked, the note moved to another notebook, an app made private: the run ends failed with a plain reason and nothing it produced is published); a result held through a conflict is asked about once more when it's applied. A finished answer always lands, paused or not: Pause stops only what would happen next, so a run paused at its end hands nothing on and gives back every line asked of it. A second opinion isn't queued behind a quick helper (refused). Every other reply, a refusal or something done without a run (remembered, watching, put back, a missing or private notebook, nothing to forget), goes through `NoteHelpers.reply`, whose words are `Shielded` (Petal's literal, or made from names, titles, words and paths each shielded whole first, a title derived from a note's whole body): a faint word that leaves the note's ink, PR link, proof and helper line as they are, giving a refused line back its runnable mark.

After a restart, or with its editor closed, nothing can run: to run an old line again, edit it (even a space). Imported, synced or tool-written text never runs anything (a paste in the editor is the person's own edit). Keyword routing never does anything by itself on words that don't ask for it: every local route (watchers, morning notes, bring back, chains, recalculation, put away, stop, pause, remember, forget, the worktree's removal) passes one gate at the end of `NoteHelp.request`, which takes it only for a plain instruction (`NoteHelp.imperative` of the route's instruction: a watcher's words before what it watches for, a chain's request, remember and forget by their verb; not a question, a condition or a negation, "check whether it's done", "don't leave me a note every morning"); anything else goes to the helper as an ordinary request. Stop watching, pause, remember, forget, bring back and put away are done on the note at once (`NoteHelp.isControl`), even while a helper works there, never sent to it as a follow-up; what Petal says then shows faintly on the note, leaving the helper's ink alone (put away is refused while a helper works).

A note whose id isn't lasting yet (`NoteShelf.lasting`: written by hand, or its id still being written) gets its id and waits for it to land before anything is registered for it. Return on a bare @Petal asks nothing: it's refused before any run is registered, with a faint "Ask Petal something after @Petal" on the note, and an empty prompt never reaches an agent (`NoteHelpers.start` fails the run). @Petal runs the person's chat AI with Petal's tools on the note's place (in the background, as the AI button's preview shows; four at once at most), the notebook's cover read first; its answer is one block of ink on the front (the next replaces it), its steps and a stamp for each thing allowed on the back (tapping a stamp takes the grant back). Allow, Don't and Buy cards show on the note; Stop and Pause are its only buttons, everything else is said in words: "bring this back Friday" (it shows then on its place, or on the Desktop), "remember …" / "forget …" (the cover's "Petal remembers" lines), "put this away" (the window's tabs, file and mail into the note, with Open all), "check this every morning, tell me under $300" (a watcher on one Mac, its time a clock in the time zone it was said in, that fetches plainly and asks the AI only when it can't read the value or the line is crossed; never buys; only words that ask again and again make one, "every", "each morning", "keep checking", "tell me when": a plain "check whether" is asked once), "make this recalculate" (the AI proposes a formula once, arithmetic keeps it), "when @Research is done, draft @Proposal" (no loops, never twice; the note it waits for is a source of the run: the note that runs must be able to read it, checked by its id and current notebook when the chain is made, when it fires and by the gate, else it doesn't fire and says so faintly), "check this against @Notebook" (contradictions as questions), and "leave me a note every morning" (Petal's own note on the Desktop).

A note on a GitHub pull request or issue, or on a file in a git repository in the home folder (the repository the file is really in, as `AgentAccess.repository` resolves it: the nearest one above it, a linked worktree's main checkout only when git made it one, so a file under a T3 worktree is its main checkout's), runs the person's own Claude Code or Codex in the note's own git worktree of that checkout (one per note, reused for its follow-ups, removed once its PR merged, or once the person says it's done and presses Remove on the note's card ("Remove the worktree for <branch>? It has no changes.", Don't the default), only after it's checked to be the note's own and clean; a checkout named in words is always checked, however many fit, and matches only its whole path (`NoteHelp.chooseCheckout`); asked once per project on the note), with the PR link and proof as ink; "have GPT 6.1 Sol look for holes" adds a second opinion's ink with its count.

Models are named in words; there are no @Claude or @Codex entries. A Private notebook is read only by a note inside it, and its helpers never show in the AI button's previews. A quick question that used notes shows them as chips; results drag out of a note (a picture as its bytes, read through `NoteStore.pictureFile`, never a path). Open all on a task, and any link a helper left, never launches an app or a script (a task can come from sync or a tool): `NoteTasks.openAll` finds a file by the one file resolver (the very file put away, by its `fileID`, then its bookmark, then its path), resolves its aliases and links off the main thread and opens it only when it's content and none of an app, executable, script, .command, .tool, .workflow, .terminal, installer package, disk image, alias, link, .webloc, .inetloc or .fileloc; anything else is revealed in Finder. Tabs open only for http and https, mail only for message:, and a window's app is only brought forward when it's already running.

## Notes on paper (phase 1)

### The file, where a note is stuck, and the pure rules (`NoteFile.swift`)

Petal Notes (`notes`): `NoteFile.swift` is its pure side, checked by `macos/checks/run.sh`: the file format (a front matter of `id`, `created`, `modified`, `places`, a cover's `color`, the quick question's `chat`, and any key a later Petal adds, kept as written; then the Markdown, one `NoteBlock` per line), where a note is stuck (`NoteStick`: passage, tab, file, window, app, desktop, screen; what only means something on one Mac while its apps run, a window's number, a process, a tab's id, and the screen itself, is said with `mac`, that Mac's own id from `notes-state.json`), a tab's runtime identity (its tab-strip button) carried across a read of the folder only to the same unchanged anchor that matches exactly once, never by position, and dropped when uncertain (`NoteShelf.carryTabElements`), which place fits what's in front (`NoteMatch`: the ranked fallback passage → tab → file → window → app; a Desktop and the screen fit no window and rank after every other place; a tab by NoteTab's rules exactly, its id or tab-strip button while the browser runs and, after a restart, a Chromium tab by its address only when it was and is the one tab with it, a Safari, Firefox or Zen tab never by address; a window after its app restarted only when one window has its title; a passage only where its whole quote is, the one place the words before and after it fit best across the window's texts, else "passage moved"; never a guess), iCloud's conflict copies (`NoteShelf.conflicts`: papers with one id; a file with no front matter is known by its path under the notes' folder, never its name alone), saving (`NoteShelf.save`: over the file only as the edit began, else both kept), a read of the folder never undoing a change made since it began (`NoteShelf.fenced`), Petal's pictures at the notes folder's root, never beside notes: one folder per note named for its id by a hash only, never a character of the id or a file's name (`Pictures/<hash>`, linked as `../Pictures/<hash>/<name>`, the same from every notebook: `NoteShelf.pictureFolder`, `pictureLink`, `resolvedLink`; `Pictures` is never a notebook, `folderName`), and the one rule for a picture link wherever it's read or written, the editor, the read-only paper, journal recovery and rescue: resolved from the note's folder and standardized, only inside the notes' root, never absolute, "~" or an address (`NoteShelf.pictureTarget`), and no symbolic link on the way (`NoteStore.pictureFile`); anything else is a broken picture, what stays inside the notes' folder (`NoteShelf.within`), the tabs on a window's edge (`EdgeLayout`: at their line, several on a line as one with a count, the rest stacked from the top, never overlapping, faded after 30 days), the room beside a window (`NoteRoom`), and the sketch's paper colors (`NoteInk`, CSS color-mix in Oklab).

### The store: one owner for every change (`PaperNotes.swift`)

`PaperNotes.swift`: `NoteStore`, the files (the root: `PETAL_NOTES`, else `notesFolder`, else iCloud Drive's `Petal Notes` when iCloud Drive exists, else `Config.supportFolder/Notes`, resolved off the main thread with this Mac's notes state at start and kept until `notesFolder` changes, `NoteShelf.cachedRoot`; notes work once both are in, `ready`; Inbox and its cover made the first time; every trash through `NoteStore.toTrash`, never a deletion), read, written and moved coordinated (NSFileCoordinator) on `NoteStore.io`, never the main thread (a file iCloud hasn't downloaded is asked for and read when it arrives), watched with FSEvents. Every change to a note goes through its `NoteSession`, the one owner of what isn't on disk yet: typed text, keep-asides (an edit to a paper that turned read only), picture bytes, a move (only its Markdown: Petal's pictures stay where they are, nothing of them copied, moved, trashed or swept; pictures a handwritten note links beside it, such as `Trip.assets/photo.png` or an older link, are copied to the same place where it lands so its links hold, never deleted where they were, a duplicate at worst and never a broken link, and a different picture already at that place, by its bytes, refuses the move: `NoteShelf.carried`, `carry`; places compared by the file system's identity, never their paths' spelling, so a notebook named in another case is the same notebook and a move to the folder it's in does nothing: `NoteShelf.canonicalNotebook`, `sameItem`; a move queued after a save that was kept beside the file stops, said on the paper: `NoteShelf.stopMove`; trashing a note leaves its pictures alone), a new note's or notebook's cover file (`ensureNotebook`, the one way a notebook is made; a name that is an existing notebook in another case is that notebook, `canonicalNotebook`; its cover written in the same queued step that first makes its folder, contained and through no link, `NoteStore.makeFolder`), a trash, Keep this one, as one ordered list of `NoteWork` done one at a time on the file queue (`NoteStore.perform`; `NoteDisk` knows where each file is), so a save or a picture made during a move lands where the note lands; a tool's work carries its asker's `live`, checked right before it's done, in retries and drains too.

Every change checks, inside its coordinated step and right before it, that the file is still the note it's for (`NoteShelf.stillNote`: its id, or for a file with none its path's): another note at that path is never written, moved, stuck or trashed (a tool's change is refused, `notThisNote`; the person's typing is kept beside it as a copy of its own note). File names never hold a secret: a new note's, a conflict copy's, a recovered or unsaved note's name is made on the file queue from its title after the vault's redaction (`NoteStore.nameRedactor`, `NoteShelf.safeStem`; a plain name while the vault can't be read; a new note shows under a plain name until then). Every write carries the exact text of the file it was made on (an editor's: what it last loaded or wrote; a tool's or Petal's own: the note as it was then) and lands only while the file still says it, or already says the new text; anything else is kept beside it as a conflict copy (`NoteShelf.save`).

### Pastes, drops and pictures

A paste or drop is recorded with its note before anything is read (`beginImport`: its sources, a file's path or the pasteboard's bytes, in the journal at once), so a note with a picture loading is never put away as empty and a quit meanwhile puts it in at the next launch (one whose file can't be read yet waits for the launch after); a paste its note can't take when its read ends, or one that ends after the notes folder changed, is put in from the journal into that note in the folder it was pasted in, and leaves the journal only once it's stored (`NoteShelf.importEnd`); after part of a paste goes into its note, the journal's snapshot advances to what landed with only the sources still waiting, never over a newer snapshot (`NoteJournal.advance`, `NoteShelf.advancedSnapshot`); recovery says where it landed (the note, a copy beside it, a file of its own, or "Unsaved notes"), and the rest of a partly recovered entry continues at that same file (unless it's the note itself, found by id), with the bytes of every picture it references kept until they're stored there (`landedAt`, `NoteShelf.continuation`); a save that kept a copy beside the file lands at that copy (`NoteJournal.landing`), and a destination that can't be read, or changed since, is kept and the rest goes to a file of its own (`NoteShelf.continueWrite`).

A rescue into "Unsaved notes" goes into a folder of its own (a hash of its note's id and the moment: `NoteShelf.rescueFolder`), carries every picture its text references, the older ones copied from where its links lead, laid out as in the notes' folder (the note in `Note`, its pictures in `Pictures/<hash>` beside it), and is complete only once all of them are there (`NoteShelf.referencedPictures`, `rescueComplete`); a picture already where a rescue, a recovery or a move wants one counts only when it's the same bytes (`NoteShelf.acceptExisting`). Each file of a paste ends on its own (`NoteShelf.sourceEnd`): one not read yet but still there (iCloud downloading it) stays in the journal and on the paper's Try again line until its picture and link are stored, whatever the others did. A pasted picture is read and decoded first (off the main thread, never on the journal's queue), then accepted: its bytes in memory and, through the session, in the note's folder in `Pictures` under a name chosen then; its reference goes into the note at once as ordinary text (the editor, or a based write). One whose bytes can't be written is set aside on the paper ("Picture couldn't be saved", Try again, Remove: the reference goes too), and nothing waits on it.

### The journal (`NoteJournal.swift`)

`NoteJournal.swift`: each person's change writes a whole snapshot of the note to a small journal on this Mac's own disk (Application Support's "Notes journal", never iCloud), on a queue of its own, atomically replacing the last: the note's id, the base of its oldest write not landed yet, its full text, and the bytes of the pictures that text references that aren't in its folder yet (`NoteShelf.journalPictures`: a paste undone takes its bytes with it).

### A note with no id of its own

A note with no id of its own (a Markdown file made elsewhere, known by its path) gets one in its front matter, written through its session, before Petal writes, moves, sticks or adds a picture to it (`NoteStore.ensureID`); the paper, its session, what waits for it and the desk's records (`onIdentity`, `NoteLocal.rekeyID`) take that id at once. Nothing lasting is kept about an id-less note, or by an id still being written (`NoteShelf.lasting`, `pendingIDs`): a paste on one first has its id written (`ensureID(then:)`) and is refused if that can't land; a tool's read gets an answer and a handle for this run only; `NoteLocal` writes to disk only records kept by a real id that's in its file (`persisted`), and a conflict paper's handle part by its note's id and a hash of its place in the notes folder (notebook and file name, iCloud versions in a namespace of their own: `NoteShelf.copyKey`). An identity change is an event every holder follows, scoped to the file itself: an id-less note's path id means something only with its file's instance (volume and inode, read with the folder: `NoteShelf.holderKey`), so the store keeps that file's old key → new id (`aliases`, `NoteShelf.current`), its path's id is retired, and a new file at that path is never taken for it; the editor (`NoteShelf.editorKeeps`: the same note keeps what's typed, saved through the note as it is now), a paste being read, a tool's request (`NoteShelf.follow`) and handles go through it before they act.

A snapshot goes once its text landed (or its conflict copy did) and every picture it references is saved (`NoteShelf.journalClears`): a picture that failed keeps it, with its bytes, until it's saved or removed, and at quit until the next launch's recovery. At launch the journal moves aside into a "recovering" folder (and any a launch before left is resumed), and each entry is put back on its own, found by its note's id, never its path (`NoteShelf.journalTarget`, `journalRecovery`: into that note while it says what the snapshot was made on, else a conflict copy beside it; no single note of that id, a file of its own; else "Unsaved notes", pictures laid out as in the notes' folder; each picture's bytes go back exactly where the saved text's link points, whatever layout wrote it, and only to a place `pictureFile` allows, else into the note's own folder in Pictures: `NoteStore.restorePictures`); an entry goes only once its recovery wrote and said so.

Quitting waits for that local queue (and for what the drain cleared in it). A tool's change shows nothing until it landed, and its asker's `live` is checked inside the coordinated write (and before each step of a move): a cancelled one leaves nothing behind. Writing that fails stays, says so on the paper and is tried again; pictures whose bytes couldn't be written are set aside on the paper with Try again and Remove, and Remove is refused on a read-only paper; with the note's editor open it's an edit in that editor (only the pictures' attachments deleted, and a line's break only when nothing else is on it, `NoteShelf.removalRange`; saved like any typing, so nothing typed and not saved yet brings them back; one undoable change whose undo puts them back and accepts their unsaved bytes again under their own names, journaled and written in the background, `NoteStore.reaccept`, and whose redo removes them again; both find the note by the editor's id when they run, `NoteStore.current`, never a key from before a move), else a based write, and either way their recovery bytes go only once a write without their references has landed (`NoteStore.retirePictures`); quitting (`applicationShouldTerminate` answers later: `NoteDesk.prepareToQuit` stops listening and narrowing, waits for the journal's queue, then drains every session and gives back every narrowed window off the main thread, for up to 10 seconds) and switching the notes folder drain every session the same way (`NoteStore.drain`); pictures in by then get their references in one based write, and writing or pictures that still can't land go to Application Support's "Unsaved notes".

### Revisions, iCloud conflicts and Keep this one

Each paper knows the file as Petal last read or wrote it (`revision`); a write goes only over that, else keeps the edit beside it ("Name (conflicted copy).md", reused only while it still says what Petal wrote there), and a file that already says it is done (`NoteShelf.save`); Petal's own changes of a note's places never count as a conflict for an open editor (`NoteShelf.rebase`); every completion that writes back (a bookmark followed, a tab followed, a recovered tab) is fenced by the revision it started from (`change(expect:)`); a read of the folder never replaces a note with work under way, or one whose open editor has typing not saved yet; an idle editor takes a newer version at once (its cursor kept when it has the keyboard), and the folder is read again when an editor goes (`NoteShelf.fenceEditor`, `editorTakesNewer`); an editor is dirty from the person's typing until its save runs, and a version held off meanwhile is taken then (`NoteShelf.EditorMarker`, `takeDeferred`).

An iCloud conflict (a copy with the same id, or versions NSFileVersion kept, grouped with their file whatever their ids: `NoteShelf.conflictGroups`) shows as read-only papers until Keep this one, session work that acts only on the papers exactly as shown (`NoteShelf.keepAllowed`: every one still there and unchanged, no version arrived since), checked again inside each coordinated write or trash (its plan always holds the current file at every path shown, its text and id, even when a version has another id: `NoteShelf.keepSnapshot`; the kept version is written only over that file exactly as shown and still that note, `keepWrite`): it writes the one kept and reads it back, marks the shown versions resolved and trashes the other files. A trash is never of an existing file Petal can't read to check (`NoteShelf.mayTrashFile`: nothing there, unreadable and its text are told apart). On quit, editors hand what's typed to their sessions first.

### The note tools' writes, and this Mac's own state

The note tools go through the same paths (`change`, the one `move`, which re-keys panels and editors for every change of a note's file), answer with what reached the disk (written, kept beside as a copy, or not saved yet), refuse a read-only paper, check their asker is still there before each change (`live`), and tell a private app's places only as what they are (`NoteStick.scrubbed`); and `NoteLocal`, what stays on this Mac (`Application Support/Petal/notes-state.json`: this Mac's id, the notes showing, where the person moved each, the last notebook per site or app).

### The desk: notes on the screen (`NoteDesk.swift`)

`NoteDesk.swift`: the notes on the screen. It listens to `WindowEvents` (Accessibility taken away hides every window note at once and given back needs a fresh read before they show, `NoteShelf.onPermission`; a drop's read is filtered for privacy again after its last wait, `refilterDrop`; a focus change away from the window shown hides its notes, tabs and pins at once and cancels narrowing waiting for it, and nothing shows again until the new front window's read is in: `NoteShelf.concealOnFocus`; hiding starts a new look, so a read already under way is stale, and gives every narrowed window its width back at once (`NoteShelf.onHide`), and a read becomes the active scene only when it's fresh, of the current look and of the app still in front, never one captured earlier such as Stick here's, which only anchors the new note: `NoteShelf.mayBecomeActive`; a note is made from a selection only when its read became active and is still active after the selection read, `NoteShelf.mayCreate`; only layout shows a paper, and a paper takes the keyboard only once it's shown, `mayTakeKeyboard`; one that asked before it was shown, like the first Desktop note, waits for layout to show it and is dropped if the person goes elsewhere first; one on a window Petal is bringing forward waits for that app and window, `NoteShelf.KeyboardRequests`) and reads what's in front off the main thread, one read at a time with one follow-up and nothing more asked of an app once its look is stale (`NoteShelf.ReadGate`, `readCurrent`), (`ClaudePanel.readFront`, the same window and tab reads, NoteTab ids and tab-strip buttons, as AI notes; the browser's tab only while some note is on a page, so no Automation prompt otherwise; the window's AXDocument and its bookmark, never for an app kept private; how many of its windows share its title), through one final privacy filter wherever the result is used, a cached one too, tagged with the private apps' generation it was filtered against (`NoteDesk.filtered`, `NoteScene.privately`: an app made private since leaves nothing but its window); a selected sentence follows `petal_look`'s rule exactly (`Assist.selectionInSecret`, in Ask and Note's button too, before anything is captured: nothing from a field holding, named for or filled with a secret, nor text holding a vault secret), is read once for a note or a tool (`NoteDesk.passage`), and is refused (no note at all) when the window, tab or private apps changed between the scene and the selection; a tab Petal can't tell apart (Safari's only tab) is never offered, its window is; every anchor of every note that fits a restored Chromium tab by address, or a window by its title after its app restarted, is decided together before any note picks its place (`NoteMatch.anchors`: all from one old tab or window, they take it; else every one is left out); a tab's note seen surely on its own tab keeps the address it shows now (`NoteMatch.followTab`), and a window's note confirmed by its live identity keeps the window's title as it is now, written fenced and without touching when it was edited, whether the window is in front or behind (a title change heard for that very process and window; never a private app's: `NoteShelf.followedTitle`; titles are heard while notes are on windows); another tab in the browser window shown hides that window's tab and passage notes and pins at once, until its tab is read again, and starts a new look so an older read can't undo it (`NoteShelf.tabReread`, `hiddenDuringTabRead`, `hidingLook`), and a file in front that no note matches makes the notes on files follow their bookmarks; finds each passage's line (the window's one text element holding its words, within half a second; a text area's own bounds for them), and while passage notes are on a window measures those ranges again on a light timer (twice a second), so a tab and its pin follow the page as it scrolls: each poll checks the remembered range still holds its quote (`NoteShelf.passagePoll`), else finds it again by quote and context, and found again and not there it's an explicit moved state (looked for again every 2 seconds at most while its note is on the window, through the scan gate, so a sentence brought back by Undo comes back: `NoteShelf.passageWatch`), "passage moved" with no line or pin (never the whole text's frame, `NoteShelf.passagePlacement`); a note whose winning anchor stops being a passage (re-stuck elsewhere) lets go of its line, pin and found state, and a pin is drawn only for a note placed on a passage now (`NoteShelf.passageGeometry`); one scan of a window at a time, later requests coalesced into one follow-up (`NoteShelf.ScanGate`), skipped when its look is stale before it starts, on a queue of its own (`passageQueue`) so restoring windows never waits behind one; the watcher is reconciled with what's placed after every layout and stops when no passage note is on the window, skips a tick while a measurement is under way, and drops measurements made for what's no longer watched (`NoteShelf.passageWatch`); a sentence scrolled above or below the visible text rests its tab on that edge with no pin (`NoteShelf.passageSpot`), and shows (hidden as GlassPanel hides: clear and mouse-through, never ordered out) the window's notes as `EdgeTabPanel`s inside its right edge (hover: the first line; click: show or hide) and `NotePanel`s beside it (nonactivating; many open, one with the keyboard; clicking away folds them; dragged, a note keeps its spot by the window's nearest corner, `NoteSpot`, below; after any change of its face, open, turned over or folded, it's placed again the one way and kept whole on its screen, `NoteShelf.wholeOnScreen`).

### Room beside a window, and the pin

A window with no room beside it is narrowed when a note on it opens, and keeps that room while any of its papers shows there, folded or open (`NoteRoom.keepsRoom`), so it's resized once and a folded paper never covers the page; it gets its width back once none shows (put away, the window left, notes off, quitting). All through one path after every change of what's showing (`reconcileRoom`, `NoteRoom.reconcile`): on one serial queue, with each window's frame from before recorded before it changes (also in `notes-narrowed.json`, so the next launch puts back what a crash left, keeping what it can't yet for the next try); folding, hiding, putting a note on the Desktop, notes off and quitting give the width back, a change cut short too (`NoteRoom.restore`); a record goes only once the window is back, gone or the person's (`NoteRoom.giveBackPlan`); a window the person moved or resized since keeps its frame; a note dragged away gives back the room it no longer needs; switching the notes folder cancels narrowing under way and gives back every recorded width at once. The pin sits one level under the notes and their tabs. A showing note on a sentence whose bounds are known has the sketch's dashed line to it (`PinPanel`).

### Picking a paper up, and where it stays (`NotePad.swift`, `NoteLayout.swift`)

A paper is picked up from anywhere on it that isn't a control or the writing being edited: all of a folded paper (its words too), an open one's top strip, letterhead row and margins, and its back. What picks it up is one AppKit view, `PaperGrab`, drawn right under the paper's words and controls and over its own surface (`PaperView.grab`, only on the desk: Petal's viewer's margin and the Petal Notes window have none): the mouse's own events move the panel by exactly what the pointer moves, from where it was pressed (`NotePanel.grab`, `drag`, `dragEnded`; never the real pointer warped, never a SwiftUI gesture behind the paper, which its opaque surface would swallow), a first click on a paper without the keyboard already picks it up, and a click that didn't move it opens a folded paper. The letterhead's two buttons, the folded corner, a card's buttons and the editor are above it and keep their own clicks; the strip, a folded paper's words and the back's own words let clicks through to it (`allowsHitTesting`, only where `grab` is set). The folded paper's SwiftUI tap and drag (`FoldedTouch`) stay for whatever SwiftUI still draws over it: both paths call the same panel, and a second call does nothing.

Over the paper itself the pointer is an open hand, closed while it's held (`PaperGrab.GrabView.point`: decided on every move by what a click there would reach, so over a control it's the arrow and over the writing the text's own). Petal is a background app and macOS lets only the app in front set the pointer, so the window server's own switch for that (`SetsCursorInBackground`, looked up at run time like Spaces') is on only while the pointer is on a paper (`PaperCursor.take`, `leave`), and a paper hidden with the pointer on it gives the arrow back (`PaperCursor.hidden`, from `conceal`). A macOS without the switch leaves the arrow: nothing else depends on it.

Let go, the paper stays exactly there (`NoteDesk.moved`): by its window, as a `NoteSpot` (an offset from the window's nearest corner to the same corner of the paper, in this Mac's `notes-state.json`), so it keeps its spot as the window moves or resizes and as it opens, turns over and folds (its stuck corner stays put: by a top corner it grows down, by a bottom one up); on its Desktop or the screen, as a point (its top-left corner). It's placed again at once the one way (`layout`), so the only move after a drop is in from a screen's edge it crossed, and it's kept whole on the screen the spot itself is on, whichever that is (`NoteSpot.frame(size:window:screen:screens:)`: a paper dragged to another screen than its window's stays there; its screen unplugged, it's on the window's). `NoteDesk.spotFrame` is the one place a moved paper's frame comes from, for layout and for the panel fitting itself when its size changes (`NotePanel.refit`), so a paper never jumps as it opens or its writing grows; a paper held by the pointer is left alone by both until it's let go. A paper with a spot never asks for room beside its window (`NoteRoom.wanted`) and is never put back beside it. New notes from ⌃⌥N and Note by a selection still open beside the window, where they cover nothing, and are dragged away like any other.

### A note on the screen itself

One more place a note can be stuck: the screen (`NoteStick.Kind.screen`, with `mac`, this Mac's id: `NoteShelf.screenAnchor`). It follows every rule the Desktop place follows. The file keeps it as written, with whatever a later Petal adds to it. It fits no window and ranks last (`NoteMatch.fits`, `Kind.rank`), so a note also stuck to the window in front shows there (`NoteShelf.placement`: the window, then the screen, then its Desktop; `Placement.screen`); otherwise it shows at its spot on every Desktop, whatever is in front, above the windows (`NotePanel.rest`: a Desktop's note sits just above the icons, the screen's floats). It's per Mac: only a place recorded with this Mac's id counts (`NoteShelf.onScreen`), and on another Mac the note simply doesn't show there. Layout is the only path that shows it (`placeDesktop`, which places the screen's notes and the Desktops' together and needs no Desktop's number for the screen's; `mayShow`), a focus change leaves it where it is (`NoteShelf.restsOffWindow`), Mission Control hides it, nothing is read of what's in front for it (`look`), and a Private notebook's is left out of Petal's pictures like any paper. Its spot is a point on the screen (the same record a Desktop note's is); with none (a tool stuck it there) it rests down the main screen's right side (`NoteShelf.screenRest`). The letterhead and the note tools say "On screen" ("also on the screen" after another place), the Petal Notes window's footer too, and a helper never takes it for a place to look at (`NoteHelp.looksAt`: only on the screen, its helper is free, as on a Desktop).

"Keep it on screen" in the letterhead's menu adds the screen to the note's places, where the paper is right now, and keeps its other places; ticked, choosing it again takes it off (`NoteShelf.screenToggled`, `NoteDesk.keepOnScreen`). A note is never left stuck nowhere that way: with the screen its only place the item is ticked and can't be chosen, and the items under "Move it to" and "Move it to this Desktop" move it. Among several places, "Take it off here" works for it as for any other. The note tools stick to it with `to: "screen"` (nothing is read of what's in front).

### Notes on a Desktop, sessions and the notes' folder

Desktop notes sit on their Desktop (just above its icons, shown while it's the Desktop showing, placed by the validated placement so a note also stuck to a window goes there while that window's read is awaited, and papers hidden on a focus change by where they're shown now, `NoteShelf.onDesktop`; a paper is shown only where its one placement says it belongs right now, by the window in front or on a Desktop showing, and every other paper is hidden: `NoteShelf.placementNow`, `mayShow`; while Mission Control is open (`MissionControlWatch`), every paper, tab and pin is hidden and nothing is shown until it ends, `missionControl(_:)`; a re-key moves every per-paper record, `NoteShelf.rekeyed`); which Desktop each screen shows is read off the main thread (`refreshSpaces`, only while a note is on a Desktop, again on every Space or screen change, heard whether or not Accessibility is allowed: `NoteShelf.spaceSignals`, and when notes are turned on: `NoteShelf.onEnable`) and layout uses that snapshot; sticking a note to a Desktop (a tool, the letterhead's "Move it to this Desktop") reads that screen's Desktop off the main thread through one function (`resolveDesktop`) and is refused, saying why, without its number, its places left as they were (`NoteShelf.desktopAnchor`); notes code never asks `focusedDock`, and a place has no mode (a note file written when the Mac had modes may still say `mode` on a place: kept as written among the keys Petal doesn't read, `NoteStick.extra`, and read by nothing); a note shows in one place only, by the window in front when one of its places fits it, else on its Desktop (`NoteShelf.placement`).

Each note's session is known by its own id, never its path: a new note's file named on disk never takes a name another note being made was shown with (`NoteReservations`, `NoteShelf.rekey`); a paper gets a session only when it's that same note's (`NoteShelf.session`), and after each read of the folder an idle session follows its note to its new name or is retired. A note renamed or moved elsewhere while Petal holds it (open or not) is followed by its id before the read is fenced (`NoteShelf.follow`): its paper, editor, panel, session and waiting work take the new path, never a second read-only paper beside it.

The store reads and watches the notes folder only once its first root is settled, and the watcher follows every later switch; a folder asked for during a switch is switched to once it's done (`NoteShelf.nextRoot`: the latest asked wins). A note dragged out of the AI button finds the window under the drop off the main thread and checks it's still there before the note is made. A window place is the same window only by its live identity (process and window number); a title tells only remembered windows with no number apart. The queue and the quit drain each claim a piece of work before doing it (`NoteDisk.once`), and nothing new starts once the drain has begun, so no piece is done twice.

Making a note: the note pad in the dock (`NotePadButton`, `notesPad`, by the AI button and Finder's on every screen's dock while notes are on; it shrinks with the icons and never moves or grows on hover): a click is ⌃⌥N, a right-click offers New note here, Open Petal Notes and "Show the note pad", and a drag takes a paper off it (`NoteDesk.dragPaper`, the same drag as out of the AI button: `PaperGhost` follows the pointer; let go over the dock it's nothing; anywhere else the note is made right there, on the window under the real pointer at that spot, else on that Desktop, the paper landing folded-size with its corner by the pointer and opening to write in from the corner it's stuck by; holding Option it's kept on the screen itself, and the paper says "Stays on screen" while it's held); ⌃⌥N (`Hotkeys`, registered on its own while notes and shortcuts are on, whichever dock is chosen: `NoteShelf.shortcutGroups`), Note by a selection (`SelectionAsk`), a drag out of the AI button (`Dock.swift`; the window under the real pointer is the one, only the paper's landing offset, `NoteShelf.dropPoints`; it comes forward, and the note's spot is recorded against that window's own frame), Stick here (the quick question: what was in front when it opened, `capture`, only the latest opening's, `NoteShelf.captureCurrent`; only once the answer is done, no reply being written and no turn waiting: `NoteShelf.stickReady`). The quick question's own panel is no paper: it always opens over the dock, in its one place, and can't be dragged (the drag and the spot it remembered were a test from before Petal Notes; `InputPanel` only fits itself above the dock now). Stick here is how it becomes a note.

### The paper and the editor (`NoteViews.swift`, `NoteEditor.swift`)

Papers showing beside one window never cover one another: `NoteRoom.stack` (pure, in `NoteFile.swift`, checked) gives every paper its frame. The place menu's two headings are "Stuck to" and "Move it to"; a place with an address has "Open this page". ## Helpers in notes (phase 2)

### What an @ line binds, and the front matter a helper keeps (`NoteHelp.swift`)

Helpers in notes: `NoteHelp.swift` is its pure side, checked by `macos/checks/run.sh`: what an @ line binds (`NoteHelp.bindings`, `mentions`, `@[Two words]` for a name with spaces) and asks (`request`), times and models in words, prices on a page (`amounts`, `pick` after its `hint`, `crossed`), a cover's memory (`remember`, `forget`), plain arithmetic (`evaluate` over a note's "Label: number" lines), chains' loops, GitHub pages and the person's checkouts (`repository`, `remotes`, `slug`, `checkouts`), and the front matter a helper keeps, read back exactly (`NoteValue`, an indented subset, in `NoteFile.extra`): `helper` (state working, waiting, done or failed, who, step, `asked`: the line it answered, `mac`, `at`), `ink` (who, text, proof, link, objections, `opinion`: a second opinion's), `steps`, `stamps` (a shielded label, grant: `always:<kind>`, `rules:<note>:<run>:<opaque id>` (the rules themselves kept only in memory, never in the note), `project:<grant id>` or `reply`, and the Mac it was given on), `back`, `watch` (the shared contract's fields plus `checked`, `at`, `tz`, `hint`, `url`, `hit`, `id`, and `amount`: the newest value exactly as read, beside the contract's `last`, which is it rounded for the corner; every threshold and delivery decision is made on `amount`, rounding only when drawn, a value told to the quick AI exactly; and `unconfirmed`: a crossing that couldn't be confirmed (no AI set up, or no explicit yes), its number, shown faintly beside the corner as "· couldn't confirm" (the corner is drawn, and its room kept, when either `last` or `unconfirmed` has a value, so a first such reading shows too: `NoteHelp.corner`); it isn't taken (the corner keeps the last accepted value), is never a hit and never opens the note; a refuted reading isn't taken either and shows nothing. Watchers work with no AI set up: a reading that doesn't cross the line needs no confirmation and updates the corner as usual), `worktree` (path, branch, checkout, remote: the note's coding worktree, keyed by the checkout's canonical path and the note, verified with git before it's reused; its branch is `petal/<a few words>-<the note's key>`, unique by construction), `task`, `calc` (label, formula), `chain` (after, then, ask, mac, since, fired), `from: petal`, and a cover's `morning` with `morningMac`. Four rules hold them together, each one nothing can go around.

### Rule: every paid call starts through one function

**Every paid call starts through one function** (`NoteHelpers.start`: a chat helper's turn, its first, a follow-up or Go on; a coding helper's; a second opinion's; a recalculation; a task put away; a watcher's question to the quick AI; a chain's run). What waits is the call, never words: its raw sources and how its words are made from them (`Call`, held on the run while it waits for its gate or Go on; a helper agent's turn waiting for room keeps only a mark, `Agent.helperTurn`, and `again`; the quick AI's line keeps `make`; a follow-up waits as the line the person wrote, `FollowUpQueue`). Right before launch `prepare` runs the one order `NoteHelp.launch` keeps, each step from what's true then: the vault's redaction settled and readable; the call's sources read and its notebook's cover resolved through `raw(paper)` (`gather`); the admission gate; and only then the prompt (and a helper's system prompt) built and shielded from those sources, thrown away and made again if a secret was saved before it's handed on (`VaultIndex.unchanged`). A step that fails refuses through `reply` or fails the run through `end`, and nothing after it happens: no words are made.

### Rule: one admission gate

**One admission gate re-derives everything from current state** (`NoteHelpers.admit`, its pure side `NoteHelp.admit`): right before a helper's words are built for its agent or the quick AI (`start`, the only place a prompt is sent), before its turn's process starts (`Agent.gate`) and before any tool answers it, and again right before that answer goes back (`Assist.handle` through `admitTool`), it resolves the note's current paper and notebook (one that moved since the run began fails: what it was told is stale), each source note's notebook access (comparison inputs carry their ids), the run's own required place, a file's as the one file resolver knows it (held on the run, not taken from `here`), and the exact pinned AI and model being available. A place or file not showing means wait; the apps kept private changed since what it was told was made means it's told again from its line through `Shielded` (a new run), or it fails when its own place's app is private now (a run takes that generation when it's made, `Run.init`, before anything can ask its gate: never a default that differs from now, so a quick helper begun after such a change starts once); anything else that no longer holds fails with its reason; a tool's admission changes the run itself (failing fails it at once, waiting parks it, paused and resumed once the gate admits: `NoteHelp.toolOutcome`), never only words back; never a fallback or a substitution, and nothing captured before a wait is used after it unless the gate re-derived it.

A completion counts only for the run whose token started that turn (`NoteHelp.completionMatches`, `Agent.turnToken`). Every helper output (an answer, a second opinion's result, a failure, a stop, Petal's own words on the note) is journaled the moment it's made, in the helpers' journal beside the notes journal (`HelperJournal`, `helper-answers.json`, through `NoteHelpers.keep`, the only way a run's output is written: one `NoteHelp.Result` per entry, a later one for the same note composed onto one still held, `Result.then`), written to its note in one change when that's one writable paper, and let go only once that write landed on that paper (`.written`; a copy kept beside it, `.keptBoth`, isn't): held whole through a conflict until Keep this one, then applied to the kept paper (only what the result holds); never dropped, and never in part (a recalculation's formula and its `done` land together or not at all).

"Have <model> look for holes" said to a note is its own request: a second opinion scheduled after the run at work, or now against the note's last answer and worktree, or "not set up"; never steering the agent. A second opinion looks at the work it reviews, its checkout chosen as a primary request's is (`NoteHelp.reviewCheckout` through `chooseCheckout`: the run at work's checkout, else the note's saved worktree's; another one named is refused plainly, to ask on a note about it).

### Second opinions

A second opinion is part of its primary run, and its result holds only its own opinion, never any ink it captured: every output of it (each turn on the way, an answer, objections, or a failure such as "not set up", sign-in or launch, or a stop) is applied onto the note's ink as it is when it lands (`NoteHelp.Result(opinion:)`), replacing only an earlier opinion of the same reviewer, never the primary (a newer answer synced in from another Mac stays). It reviews the note's answer as it is when its turn starts and records which one by a hash of that primary ink (`reviewed`, `NoteHelp.inkHash`); when the answer on the note is another one, the paper and the note tools say "reviewed an earlier answer" with the opinion (`NoteHelp.reviewedEarlier`); one working in the note's saved worktree starts only once that worktree is checked as a coding follow-up's is (where Petal keeps this note's worktree of its saved checkout, `NoteHelp.reviewTreeOK`, then git: that checkout's, on the branch stored: `NoteHelpers.ownedTree`, the one check every use and every removal of a note's worktree goes through, so a worktree switched to another branch or saved pointing elsewhere is never removed, and the note stops looking after it); a reviewer outside a worktree is bound to the note's place through `NoteHelpers.bind` like any run and follows re-sticks (`Run.Kind.placed`).

### The open paper's height

The open paper is bounded to the screen (`NoteHelp.paperHeights`, with the controls' measured height): the helper's ink scrolls past what fits (`BoundedScroll`), and its controls (Allow, Don't, Buy, Stop, Pause) stay pinned outside the scroll; a card's form or question scrolls within what's left (`NoteHelp.formRoom`) with its buttons (Submit, Allow, Don't, Buy) measured and kept below it.

### Rule: every helper run is one `RunToken`

**Every helper run is one `RunToken`** (`NoteHelp.swift`, thread-safe), made before any setup and carried by everything it starts: Brain's queue admits its calls (`Brain.ask(key:token:provider:gate:make:)`; a watcher look has its own token, kept with the watcher and cancelled when it's paused, stopped or changed) and the chat's waiting queue starts its turn (`ClaudePanel.startWaiting`, `Agent.admitted`) only while it runs, and each git step and each process is bound to it; a paused or stopped token is never admitted and ends what it has running; Pause suspends admission and Go on restores what was pending (a call waiting, a turn queued, or "Go on" in the same session). Every Stop goes through `NoteHelpers.stop` (the note's, the AI button's preview, the pointer's), and ends what the run was doing in apps; it clears the helper line and writes nothing else (the note's ink stays as it was, with a faint “Stopped.”).

What a run does in the person's apps ends with every change of its token's state, in the one place a token changes state (`RunToken.transition` and `complete`: Pause, a tool's park, Stop, a failure, its end): `RunToken.actions`, bound by the helpers to `ComputerUse.end`, is called first and synchronously, before its process is ended, so no path can pause a token without ending its actions; and every pending press, key or fill is bound to the token itself (a helper's `ComputerUse.Session` cancel is `Acting.Cancel(run:)`, every job made under it) and reads it right before acting, on whichever thread, so one still waiting never goes. What the person says to a run while it works waits with that run's token, as the line they wrote (`FollowUpQueue`): Stop clears it, and nothing said to a stopped run is sent in a later one; the chat's waiting turn is likewise started only under the token it was sent with.

An automatic approval (an Always given earlier, or Full access) is registered on the asking run's token before it goes ahead (`Assist.ask` through `NoteHelpers.authorized`), so taking that Always back cancels every run that used it. A run holds every authorization its note was given on this Mac (follow-ups inherit them) and any it's given, so taking a stamp back cancels every run holding that grant, whichever note it's on (`TokenTable.revoke`: an Always for a checkout is shared). A quick run (recalculate, put away) is begun again on Go on; it uses the AI named in its line only when that's set up ("not set up" otherwise, never another), and its call to the quick AI goes through `start` like every paid call, its words made only when its turn in the quick AI's line comes (`Brain.ask(…, gate:, make:)`: waiting keeps it queued, failing fails its run); Brain picks each call's own AI first (the one named, else the chat's) and only then checks that one is ready. A helper's outputs say what happens to the note's helper line explicitly (`NoteHelp.HelperChange`: keep for a turn on the way, clear on Stop, set when done or failed), so a stopped helper never stays marked as working.

### Three outcomes, and a watcher's look

Every run ends in exactly one of three outcomes, reported once through its token (`RunToken.complete`): succeeded (the agent's clean exit with no error event), failed (its reason as failure ink on the paper and `helper.state = failed`: a missing API key, a launch error and every guard report it through the same path as a turn's end, `Agent.refuse`; an authentication failure is classified as failed before any interruption, `RunToken.classify`, with Settings › AI's button on the ink; a recalculation with no formula that adds up fails, and a watcher's hit needs an explicit valid yes), or stopped; `run.sh` checks that every early return of a turn and every run guard reports one. Only a succeeded run advances anything (a reviewer, a chain's next step: a chain registers its run before `fired` is written, checks it again once it landed, then goes through `ask` like any run). A watcher has an id (a UUID made anew on every change of it); a look writes back only its own fields while that id still matches and it isn't paused, and the note says a crossing only from that write's own "newly crossed" result (`NoteHelp.applyLook`).

### Everything a helper produces is shielded as it arrives

Everything a helper produces (answers, steps, second opinions, proof, PR links, failure reasons, a quick call's line or formula, the words a watcher's AI found, a stamp's label) is shielded whole the moment it arrives, before anything touches it: it arrives as a `Said` and only `NoteHelp.shielded` turns it into ink and steps, through the vault's redaction `petal_ui` uses; ink can only be made from `Shielded` (`NoteHelp.Ink`'s only initializer), steps go on only as `Shielded`, and proof, links and finish lines are derived from the shielded words. Fail, don't hold: a run starts only when the vault's redaction is settled and readable (a line is refused with a faint "Petal can't check for your saved passwords right now. Try again in a moment." and stays runnable; a chain waits for a later tick), and any output arriving while the vault can't be read ends its run as `failed` through `end` with those words, the output dropped unshown and the line runnable again; nothing is ever kept unshown (an earlier Petal's `helper-unshown.json` is deleted on launch, on this Mac only).

A run succeeds when its answer is accepted and shown, not when its AI finished (`NoteHelpers.complete`: done, its line kept used, a second opinion asked meanwhile handed on with its line, every other line asked of it given back, `FollowUpQueue.settle`). The boundary is the helper's agent itself: every provider event of a helper (a note's run) is shielded whole the moment it arrives, in order on its ingestion queue (`AgentIngest`, `Agent.shield`), before `activity`, the helper bar, the AI button's previews, the note's back or anything else reads it; a helper's text, steps, errors and the labels of what it asks to run are kept only shielded, and a helper's event the vault can't shield fails its run. An ordinary chat's events and its turn's end go straight to the main thread, never through that queue and never waiting on a vault read. `Agent.activity` is `Shielded` for every agent, since it shows outside the chat's own panel (the AI button's preview, a note's status line): an ordinary chat's step, and Petal AI's caption while it uses an app, are shielded where they're made with no wait and no hop (`Agent.shown`, `NoteShield.now`: redacted at once with the vault's index when it's already made, `VaultIndex.cached`, which never reads the Keychain; else a plain "Working…", the index made in the background for the lines after); a caption carries its turn and is dropped once that turn is over (`Agent.caption`).

A helper's cover is read before it's told anything: no cover is none, and one that can't be read right now (not downloaded, unreadable, two versions) is asked of iCloud and waited for, at most 15 seconds, then refused with a faint "Couldn't read <notebook>'s cover yet", never run without it. A watcher's results never touch the ink or the helper line, so they can never release a chain: a look is its own kind of output in the helpers' journal (`HelperJournal.Kind.watch`, only `watch`, landing only on the watcher it was made for), its value in the corner (the newest, the ones before struck); a confirmed new crossing is told by the note itself, summoned open, and `hit` is kept only once the paper showing that very value (its exact `amount`, landed) was on the screen on a face with the watcher's corner, folded or open (`NoteHelp.delivered`, `NoteHelp.told`), so a crossing the person never saw is told again by the next look. The quick AI's queue (`QuickQueue`, Brain) takes each call out before anything is called back and never calls back inside a pass: what it drops is answered later (async), asking it again is async, and a helper's gate never ends its run inside a pass.

### Rule: what a helper tells an AI is `Shielded`

**What a helper tells an AI is `Shielded`** (`NoteShield.swift`): a type only NoteShield makes, from text redacted whole (a place filtered for apps kept private first, its words and sentence derived after); its string interpolation takes only other `Shielded` values and numbers, so a raw string can't be put into a prompt; `Agent.send(_: Shielded)` (a helper's agent takes nothing raw), Brain's helper calls and every prompt builder (`NoteHelp.Told`) take nothing else; follow-ups, Go on, watcher fields, places, covers and chained answers all pass through it, and `macos/checks/run.sh` checks that raw strings fail to compile there. A helper's whole system prompt is `NoteHelp.system`, only `Shielded` parts (the place's words, the person's own notes for the AI and Petal's memory of them, then the brief), set as `Agent.helperSystem`: the chat's own instructions, with their window and tab titles, are never used for a helper.

Checking against a notebook shields each of its notes whole before any title is taken or anything cut (`NoteHelp.comparison`). Nothing said of a note, in a prompt, ink, a reply, a step, a stamp or a source chip, is cut from raw text: a chain's done note is carried as its whole body (its title derived after redaction, `Told.after`), a morning note's lines and a quick question's chips are derived from shielded bodies, and a wait's reason never names the place or file (`waitingForPlace`). What a helper is told is whole sources only (`NoteHelpers.Raw`: the person's whole line, the note's whole body, a page's whole text, a tab's title and a file's path whole): nothing is cut or parsed out of note text before it's shielded, and what a prompt needs of it is derived from the redacted text (`Shielded.spoken`, the line without its @Petal; `.rows`, a recalculation's labelled numbers, a row any part of which was redacted left out; `.watch` and `.chainAsk`, what a watcher or a chain keeps and later tells, derived when it's made).

A session's later write made on what its predecessor kept beside the file (a conflict copy) lands on that copy too, checked against the copy's own id (an identity write's copy has its new one), never back at the original base to make a third paper (`NoteShelf.carryTarget`, `NoteDisk.State.carry`). A follow-up goes to a running helper only when it names neither another checkout nor another AI or model than the run's (a path named is checked against the run's own checkout: a second opinion in a worktree keeps its verified one, and a run with none never takes one); otherwise it starts its own run, with its own checkout choice and Allow, or fails "not set up" (`NoteHelp.followUpTarget`). Claude's command rules allowed in a run belong to that run's token (`RunScoped`): a new run on the same note starts with none. A helper whose turn ended asking the person (Allow or Don't on a command) is the same run going on: it keeps its place among the four at work (`Agent.holdsPlace`, `ClaudePanel.working(besides:)`), and Allow's continuation is that run's next turn, a call through `start` like every other (`Agent.takeAllow` takes the rules and sends nothing; `NoteHelpers.allowDenials`): it never waits behind another note for room, and through any other wait (its gate, a pause) the call stays with the run; a run that ends while it holds a place frees it for the next one waiting (`retire`).

Only a real Always (`always:<kind>`) is shared between runs; Allow once, Buy and a run's Claude rules are scoped to their note and run (`once:<note>:<run>:<kind>`, `rules:<note>:<run>:…`). A model the person names whose AI isn't set up fails ("Codex isn't set up in Petal", with Settings › AI), never another instead (`NoteHelp.providerChoice`). Every watcher crossing, read plainly or found by the quick AI, needs an explicit yes before it's a hit, and a hit stays while the value stays past the line (cleared only once it comes back, never re-armed); with no confirmation it shows "Looks under … , not confirmed" (`NoteHelp.watchVerdict`). A coding helper's proof is only its own "Proof:" line ("No proof given" otherwise, in plain words), its finish line shown apart.

### Files, Petal's viewer and a helper's place

A running helper follows its note's places when they change, once `here` is recomputed (`NoteHelp.follow`, called from `NoteDesk.apply`): its required place (`run.requiredPlace`, `NoteHelp.requirement`) and its tools' target are set together in one step (`NoteHelpers.bind`), its tools look at the new place, `ComputerUse.placeChanged` drops what it read or queued for the old, and while the new place isn't in front its default look and act are refused (`ClaudePanel.helperWaiting`), never taken from the old scene or what's in front. Its setup reads nothing from disk on the main thread (the person's notes for the AI are read in `NoteHelpers.tell`, off it). Everything helpers read or write on a cover (its instructions, "remember", "forget", morning notes) goes by the same rule as privacy: the file named "About this notebook*.md" in the notebook's own folder, never a note that only says `cover: true` (`NoteHelp.coverChoice`); while the cover is in conflict (a copy or a version beside it) helpers write no memory and say the cover needs a choice first.

### Coding helpers and the clock

Coding helpers find a repository's checkouts from the home folder's (and ~/Projects', ~/Developer's, ~/Code's) `.git/config` remotes, and a file's from the repository it's really in (`NoteHelpers.repository`), off the main thread, ask `code:<checkout>` once on the note, and work in `Application Support/Petal/Worktrees/<checkout>-<note key>`; a pull request's head is fetched from the remote that is its repository into a ref of the run's own (`refs/petal/<run>`, deleted once the worktree is made; never FETCH_HEAD), and when that fails nothing is made (never the default branch instead); an issue (or a file's checkout) starts from the remote's own default branch, asked with `git ls-remote --symref <remote> HEAD` and fetched into the run's ref, and when that can't be told nothing is made (never the checkout's HEAD). A helper's answer is kept whole in the note; only the paper shortens it. The `mac` in the file is a label: an entry that is only in a file (synced, imported, written by hand or by a tool), or whose words were changed there, or that was copied onto another note, stays in its file as it is, is never fired, looked for or written back; a watcher's paper says "another Mac". The one-time taking of the ones already going waits for the whole folder to be read (a file iCloud hasn't downloaded yet), for at most 20 turns of the clock; the person setting one up takes them at once. Taken before the folder was read whole, the rest are added, once, when it is (`NoteLocal.adoptPending`, kept across launches; `NoteHelp.standing(_:merging:)`: a note's one already kept stays as it is). ### The canvas

A canvas (`NoteCanvas`) is the notebook's `.canvas.json` (each note's spot by its own id, never an id-less note's path; areas; arrows between note ids; words; zoom). Every element has a stable id and the time it last changed (`at`), and a removal leaves a tombstone (`removed`), so versions merge element by element (`NoteCanvas.merge`: the union, the newer winning on one id, a removal beating anything older and losing to anything newer). A change is only an edit made, inside one coordinated write, on the file as it is merged with every unresolved `NSFileVersion` of it, written atomically, after which the versions merged are marked resolved (`NoteStore.writeCanvas`; reading a canvas with versions waiting does the same with no edit); a version Petal can't read is left out and unresolved; every key this Petal doesn't know, at the top or on an item, is kept from the file and from every version merged, and a version whose unknown keys can't all be kept (one holds another value than the file's) stays unresolved (`NoteCanvas.merge`'s `whole`); a file with anything Petal can't read is left as it is.

### Canvas edits

Canvas edits work like notes (the one way a canvas is written is `NoteStore.writeCanvas`, which checks its binding again inside its coordinated step, right before writing, through `notebookFor` against the notes' folder as it is then, `bindingHolds`; no longer that folder, nothing is written and the edits and journal stay, as `stillNote` does for notes): each is journaled the moment it's made on this Mac's own disk, on the notes journal's queue, in its folder's `Canvas` (`NoteJournal.keepCanvas`: one entry per notebook, found by its binding, never its key (`CanvasQueue.folderKey`, fixed when the entry is made), with the whole canvas the edits made (the last canvas Petal read for it, merged: `CanvasEntry.snapshot`), so a rescue keeps everything; journal writes say whether they landed, and an entry moved to another key loses its edits only after the new one holds them, `NoteJournal.moveCanvas`; the cover fields recovered at launch are journaled again before their moved-aside copies go, and only when every one was written, `rejournalCovers`; a notebook whose folder isn't read yet takes no edit and says it's waiting for it to download), kept in memory in order with its own time and id (`canvasWaiting`, `CanvasQueue`; the journal entry only ever gains edits, by id, and loses only the ones a write acknowledges, `ackCanvas`; a write's completion acknowledges exactly the edits it wrote, and does nothing once a drain or a switch of folder came after it started, `canvasGeneration`), and applied only through the same timestamp and tombstone merge as versions (`NoteCanvas.applyingMerged`), so a retried or recovered edit never wins over anything newer.

A write that fails keeps them, the canvas says "Not saved yet" (`canvasUnsaved`), and they're tried again (2 s, doubling, at most a minute) wherever the cover's notebook is now; its notebook gone, they're rescued into Application Support's "Unsaved notes". Quitting writes nothing to the notes' folder for them (it waits only for the journal's queue); at the next launch the canvas entries are moved aside before the notes' journal is (`canvasLeftovers`, since the notes' recovery removes its own folder) and put back by their binding after the notes (`recoverCanvas`), else rescued; an entry goes only once one of those wrote. Arrows and spots are kept only by notes' own ids once they've landed in their files (`ensureID` first for an id-less note and for one whose id is still being written or whose write failed; each gesture keeps its own time through the wait, so a later gesture always wins; an area moved with its notes is saved as one move only once every note in it has its own id, else refused and snapped back, `NotesModel.moveGroup`, `CanvasQueue.groupMove`); notes without a spot are laid in rows below everything else, not written until moved; the store counts its reads of the folder (`reads`), so the canvas is read again after each.

### Private notebooks

Private notebooks (`NotePrivacy.readable`, on an existing notebook's actual folder name as read, never cleaned up, so a Private folder renamed "Health." in Finder stays Private; a destination an asker names must be readable both as given and as the notebook the store would use for it, cleaned and in any case, `destinationReadable`; a notebook whose cover is there but not read yet, or any version of whose cover says so, is Private; a cover in conflict or not read is never changed): the note tools find, list, read, write, move and stick a Private notebook's notes, and list its name, only for a request from inside it (`asker`: the note PETAL_NOTE names, by id; its notebook), and refuse writing or moving into it otherwise; right before each answer is handed over (after the redaction's wait), every notebook it tells of (for a search, every match its count includes, not only those listed; for an error, every candidate it names), and every note it returns followed by its identity the way tool requests are (`repick`, `NoteShelf.follow`: its file, or its id through the store's aliases with its file's instance, so a note given its first id meanwhile is found where it is now; one that can't be followed withholds the answer), is checked again against the asker's access as things are then (`NotePrivacy.deliverable`), and nothing is told when one turned Private: every answer, success or error, leaves through one delivery function (redaction, then this fence); every picture Petal takes (petal_look's screen and window pictures, the AI button's note previews, the dock's window previews, any `SCContentFilter` Petal builds) leaves out each of Petal's windows showing a Private notebook's note: a paper, an edge tab, a notebook's fan (followed at once when its notebook turns Private while it's open, `Popups.notebookPrivacyChanged`) and the Petal Notes window on one (its page, a search hit, a view) (`NoteDesk.privateWindowNumbers`, `NotePrivacy.excludedWindows`); a picture of one of them alone is never taken.

Those windows also ask macOS not to share them (`sharingType` none), a best effort only: macOS doesn't keep them out of other apps' screen recordings, and Petal doesn't promise it. Phase 2 follows the same rule: a helper reads another notebook's cover or notes only through `NotePrivacy.readable`, and the AI button's preview leaves a Private notebook's notes out.

### Covers

A notebook's cover is its cover-named files only (`NoteLibrary.isCoverName`): "About this notebook.md", its iCloud versions and its conflict copies (any name starting "About this notebook" and ending ".md"); `cover: true` in any other note counts for nothing (not its privacy, color or view) and stays in its file as written (`coverFlag`), except that one also saying `private: true` is a sign a cover lost its name, so its notebook's privacy is unknown (Private) until the person resolves it (`NoteLibrary.strayPrivateCover`). A cover's conflict copies and recoveries always keep the cover's name, "About this notebook (conflicted copy).md" (numbered when needed), never its heading's (`NoteShelf.copyStem`); Cover ids are unique: a read that finds one cover id in two notebook folders (a notebook duplicated in Finder) gives the folder whose name sorts later a new id, a UUID made from the old id and that folder's name so two Macs doing it at once write the same one, through the cover's session (`NoteLibrary.duplicateCovers`, `renewedID`, `NoteStore.reidentify`; the old id stays with the other notebook and nothing kept by it moves); until it lands that notebook is Private, its canvas and cover fields keep to its folder, a canvas entry its binding can't tell apart is never written there, and is rescued once its ambiguity runs out, and an exact handle two papers share is refused as ambiguous (`NoteShield.find`).

A write landing makes its session know the note by the id in the text it wrote; a write whose file already says exactly its text has landed, inside the identity fence too, so two Macs renewing one cover at once never make a conflict copy (`NoteShelf.alreadyLanded`); and after every read an idle session still waiting for an id is reconciled with its file: landed when the file has it, else dropped; either way the session, files queue and paper first take the id, path and text the file holds, and only then are its waiters told (`NoteShelf.reconcileID`, `reconcileIdentities`), so a renewal kept beside the file as a conflict, or a conflict since kept, leaves nothing waiting. The canonical cover's name is matched case-insensitively, as the file system does (`NoteLibrary.isCanonicalCover`, used everywhere it's compared).

### Cover conflicts and unknown privacy

Cover conflicts are per notebook folder, by file name, never by id (`NoteShelf.conflictKey`): every cover-named file in one notebook's folder (the cover, its versions, conflict copies, recoveries) is that notebook's cover group, whatever its id, shown read only with Keep this one and counted for privacy until resolved; covers in two folders never group (a notebook duplicated in Finder keeps its cover's id). Keep this one on a cover's conflict writes the chosen version to "About this notebook.md" in the chosen paper's own folder and reads it back before trashing the others (`NoteShelf.keepTarget`). A notebook's privacy is unknown (so Private) while its folder couldn't be listed or any of its cover files wasn't read (dataless, unreadable, its details not read: `NoteLibrary.notebookUnknown`, `privacyUnknown`); other notes still downloading don't matter, and it's public once every cover file was read and none says Private. Whether the cover can be written is kept apart (`coverUnread`: the cover file and its versions read; its conflicts the store's to see), so a downloaded, conflict-free cover is written even while other notes still download.

### One binding for everything pending against a notebook

Everything pending against a notebook (canvas edits, their journal, cover field changes like Private) is bound the one way (`NotebookBinding`: the notes' folder it was made in, the cover id then, the folder's path under the notes' folder, and the folder's volume and inode; never resolved against another notes' folder, `otherRoot`, which waits for its own under the same limit as ambiguity, or is rescued at the next launch; every binding operation, resolving, renewing (`rebind`, `NoteShelf.renewing`), writing and rescuing, takes the current notes' folder and never matches another's entries against it).

### One session per notes' folder, and one way a folder comes into use

Everything kept for the notes' folder in use is one `RootSession` (what's read, sessions and their work, in-flight markers, ids being written and renewals, cover fields and canvas edits waiting, every retry and ambiguity timer): a switch of `notesFolder` ends it whole and starts a fresh one; every completion, timer and deferred action captures its session (`NoteStore.current`, `onMain`, `later`) and, for a notebook action, its binding (the Petal Notes window captures both before any dialog opens, `NotesModel.dialog`), and does nothing once either changed; a folder comes into use the one way, at launch and at every switch alike (`NoteStore.switchRoot`), as one chain in which each step is started by the one before it, so none can overtake another: (1) the old folder's session ends and is drained by Phase 1's drain (`NoteStore.drain`: every note session drained, pictures in by then get their references in one based write, what still can't land goes to Unsaved notes, and the journal's entries stay until stored); (2) this Mac's journal is put back for the new folder (`NoteJournal.prepare`, then `recover`: journalRecovery, restorePictures, pastes read in): at launch the whole journal as a launch always took it (every note entry, the canvas entries through `recoverCanvas`, the cover fields), on a switch what was made in that folder (`leftovers(forRoot:)`, its cover fields and canvas edits); (3) the folder's first read; (4) what was pending for it (cover fields, canvas edits) is replayed with that read through Petal's own path (`apply`, `landCover`, `pumpCanvas`), which never passes the gate for changes from outside; (5) only then are notes ready (`NoteStore.notesReady`).

Until then nothing from outside is taken, as at launch: no new note, editor, paste, move, canvas or cover change, and no note tool; every way in, ⌃⌥N, Note by a selection, the drag from the AI button, Stick here, the note tools, the Petal Notes window, opening a paper, goes through `NoteDesk.takesChanges`, which says "Petal Notes are getting ready". An editor's refused save follows one rule, the viewer's phase's (see the note's editor never dropping a refused save, under Checking it): it never advances what the editor counts as saved or clears its dirty marker, and it's tried again. On top of it, for a switch of the notes' folder: before the switch every editor is sealed (`NoteEditorHandle.seal`: its input-method composition committed, its text no longer editable, what's typed saved) and Petal's viewer closes its margins' editors (`Viewers.folderSwitching`), and text that still arrives after the switch began goes to the drain of the folder it was typed in (`NoteStore.drainLate`: journaled with the pictures and pastes its snapshot held, then written as the drain writes, to Unsaved notes when it can't land; `NoteDesk.write` tries it before journaling a refused save for the next launch), never dropped.

### The viewer under the same gate, dialogs, and what can't be told apart

Petal's viewer is a notes context under the same gate: its New note button and ⌃⌥N in a viewer (`ViewerModel.newNote`, `make`), its margin's editors (`marginEditable`, read only until notes are ready, at launch too) and its letterhead's menu (`NoteDesk.restick`) go through `takesChanges`, and the viewer's tools that tell or use the notes (`petal_view`'s count, `petal_note_pdf_comments`) wait for `acceptsChanges` as the note tools do. The Petal Notes window asks the person anything only through `NotesModel.dialog` (the folder's session and the notebook's binding captured before it opens, both checked before its answer is applied; `checks/run.sh` refuses any alert, sheet or panel made elsewhere in the window) and found by one rule (`NoteShelf.notebookFor`): the same folder; else the same path whose cover id is the recorded one or its renewal; else the recorded cover id when one notebook has it and its path or folder matches too; two candidates, or a partial match only, are ambiguous: never written to any notebook, landing as usual if it resolves, and rescued whole into Unsaved notes (out of the journal) once ambiguous for 10 minutes of complete reads (`NoteShelf.ambiguityExpired`) or still so at the next launch's recovery, so nothing waits unseen forever; gone (rescued the same way) only when nothing matches by folder, path or id after a complete read.

A cover change that's ambiguous is never applied by a guess: one making a notebook Private makes every notebook it could mean Private meanwhile, for everything Private covers (privacy fails closed, `CoverFields.failClosed`, `NoteShelf.candidates`); one making a notebook public, or any other field, changes nothing; after the same 10 minutes of complete reads, or on the first complete read after a launch recovered it, it's dropped, out of the journal, and the person is told plainly ("Petal couldn't tell which notebook to make Private. Set it again.", `NoteStore.judgeCovers`); one whose notebook is gone after a complete read is dropped. A cover id renewed on a folder rebinds what's pending for that folder in the same step, in memory and the journal (`NoteStore.rebind`, `NoteShelf.renewing`), so a duplicate that kept the old id never inherits it. Cover changes waiting are kept per notes' folder across a switch of `notesFolder` and applied only in their own (`CoverFields.target`); they're replayed only after a read's conflicts are rebuilt, never onto a cover in conflict.

Canvas edits whose notebook isn't found are rescued only once the folder was read completely (`NoteShelf.notebookFor`'s `complete`; `NoteStore.read`'s `complete`: false when any listing, any file's details or any file couldn't be read, or a file is still downloading; absence counts only after a successful listing). A note held in memory whose notebook the latest read didn't find counts as in a Private notebook (`NotePrivacy.privateBooks`): unknown, never readable from outside it.

### Notes on people

Notes on people: the place kind `person` (`title`: the name, with what tells the person apart: `contact`, a vault contact's id when exactly one contact has that name, or else `handle`, the chat's own address for them, an email or phone number its header shows; never a contact's details), ranked after a file and before a window. A person's anchor keeps the app they were noted in, only so the tools are told "a person" once that app is kept private (`NoteStick.told`, the same scrubbing as every place of a private app); where the note shows never looks at it. A note dropped on another window than the one read takes nothing of the read window, its person least of all: the person comes from the target window's own header or there is none (`NoteScene.retargeted`). A person is stuck to and found only by the chat's own address for them (an email or phone number shown in the same header element their name was read from, `PersonRead.parts`, `handle(person:headings:)`; never the window's title, Mail's being the subject, nor another element: no address there, no person anchor), with their vault contact attached only when exactly one contact has that address (`PersonRead.identity`, `contact(handle:)`, `matches`): a name alone, however unique in the vault, never, so without an address the note goes on the conversation's window.

The vault's contacts (ids and names) are read off the main thread at most once a minute while a chat app is in front (`NoteDesk.contacts`); `NoteDesk.read` works out the person in Messages, WhatsApp, Telegram, Slack and Mail through Accessibility (the window's title, its headings and its toolbar's words, a few hundred elements in a third of a second, off the main thread; Slack by its title's "(DM)"), never from an app kept private (`NoteScene.privately` drops it), and only one person or none (`PersonRead.person`: two candidates that disagree, a channel or a group of several: none); the note shows beside that conversation in any of those apps as an edge tab like any window note; while a note is on a person and a chat app is in front, what's in front is read again every 1.5 seconds through the same read gate (a click on another conversation makes no event Petal hears). A group chat with a one-word name can't be told from a person.

### A notebook in the dock, and a note dropped on an app (`NoteDock.swift`)

`NoteDock.swift`: a notebook kept in the dock is a folder stack (its folder in `stackFolders`, the dock's own stacks; `NoteDesk.notebook(forStack:)`) drawn as a pile of paper in its color (`NotebookPile`), whose click fans its newest papers up (`NotebookFanView`, `NoteFan`); one clicked opens on its own. A note dragged (type `tech.edgetr.petal.note`, declared in build.sh, its id only) onto an app in the dock, on the layer strip or the SwiftUI slots, is used there (`NoteDesk.use`, `NoteDrop`): Mail gets a new message with its words and pictures (`NSSharingService` compose, left as a draft); Calendar a new event from its words (the first time they name from now on, else tomorrow at 9:00, said so), asked first and added through EventKit's write-only access (`NSCalendarsWriteOnlyAccessUsageDescription`); any other app comes forward with the note's words on the clipboard, said by the AI button.

Nothing is ever sent.

## Petal's viewer (phase 4)

### Opening a document, and its state

Petal's viewer (`Viewer.swift`, `ViewerViews.swift`, `ViewerTools.swift`; `ViewerFile.swift` its pure side, checked by `macos/checks/run.sh`; `ViewerSnapshot.swift` its snapshots and `Petal --viewer-check`): opened from a note's file place or a sentence noted in Preview (the letterhead's menu: Open in Petal's viewer, offered by `ViewerFiles.offersViewer`), by dropping a file on a viewer or on any Petal Notes area that adds `.onDrop(of: [.fileURL]) { ViewerDrop.take($0) }` (the Petal Notes window), and by `petal_view` (its asker checked right before anything is shown: a request that hung up opens no window), which waits for the document to be read (up to 120 seconds: Quick Look and iCloud) and, still being read then, says it's still loading, never a count of 0 pages (`ViewerModel.whenLoaded`), and that the viewer was closed when it closes first: every waiter (a load, a selection, the file's identity, a place on its way: `herePlace` is registered until it's answered, exactly once, so a late vault result is ignored) is in one registry that closing settles at once (`settleAll(.closed)`); one function owns the document's state (`ViewerModel.transition`: loading, loaded or Quick Look's own view, failed, closed): entering "loaded" takes the current generation's unit and happens only through its `accept`; leaving it for anything else (a failed load, a refusal by the path rule, a file not found, closing) invalidates every outstanding load and thumbnail generation, clears the pages, the selection and all anchor state (identity, bookmark, stamp) and settles every waiter with that outcome, so a load still under way never undoes a refusal and a vanished file leaves nothing to anchor to; a load that fails (a corrupt PDF, a file swapped for one it can't read) keeps nothing of the file before it (identity only ever from the current accepted read) and sets what went wrong before it ends, so the answer says it.

What the viewer and the note tools put in What Petal AI did (`ai-history.json`) names a file only through the vault's settled redaction, and leaves it out while the vault can't be read. A page or slide asked for must be a whole number from 1, checked before any arithmetic (`ViewerPages.requested`); asked for while the document loads or reloads it's kept for the finished document (`ViewerModel.ask`, `wantedPage`), never checked against a page count that isn't that load's, and shown clamped to the pages it has (`ViewerPages.clamped`; `petal_view` says when it wasn't one).

### One path rule

**One path rule** (`ViewerPath.check`, off the main thread, at every open and every reload or file followed): the final destination resolved fully (every link, every ".."), its canonical path (`canonicalPathKey`, the file system's own casing) inside an allowed root, compared by components: the home folder (a regular file the person owns) or a volume mounted under /Volumes, an external drive or a network share (a regular file the person can read: ownership there is often ignored; /Volumes itself isn't a volume); of a kind the viewer shows (`ViewerKind`). Where the file is is what matters, not the way there: a link out and back to a file in an allowed root is fine; anywhere else (/tmp, /private, /System, /Library, another person's home) is refused. It holds for every open the person makes and for `petal_view`. The PDF comments write only beside a PDF the rule allows and only into a folder the person can write (`ViewerPath.writable`); versions read only such a file and write only into Petal's own versions folder, and a version's copies are read and written only through descriptors (`ViewerVersionStore`): Petal's versions root opened once (`O_DIRECTORY | O_NOFOLLOW`), each set's folder pinned when it's made (its device and inode), and every read opening that folder again from the root's descriptor, checking with fstat it's still the pinned one, then the copy with `openat(…, O_NOFOLLOW)`, a regular file, read from that descriptor; a folder or copy swapped for a link or another folder is never read and shows "Can't be shown", while an atomic save inside the folder reads fine; removing a set (replaced, its viewer closed, a cancelled copy, the launch's sweep) deletes only Petal's own copies still exactly as it wrote them (the set's manifest, `.petal-made.json`: each copy's inode, size and modification time from fstat right after writing, `ViewerVersionStore.Made`); a copy someone edited or replaced, and anything an agent added, is their work and goes to the Trash at most (`ViewerVersionStore.trash`, only while its path is still that very entry), never deleted; it lists and deletes through descriptors only (`fdopendir`, `unlinkat`, subfolders with `openat(O_DIRECTORY | O_NOFOLLOW)`, `ViewerVersionStore.empty`), never an absolute path. A load, a reload and a file followed (`fileChanged`) are checked before anything is adopted or read; refused, the viewer shows "This file can't be shown." and loads nothing.

### One window per file

One window per file (`Viewers`, `ViewerModel`): a #ececf0 window with a 50-point bar (the name, "Page 3 of 9" or "Slide 3 of 9", "Updated just now", New note, Open in <app>), the pages as thumbnails on the left (drawn off the main thread from a copy of the document of their own), the document in the middle, and a 350-point margin.

### Loading: off the main thread, one load at a time

Nothing of a file is read, parsed or drawn on the main thread: a PDF is read coordinated (NSFileCoordinator, so iCloud brings it down first) and parsed on `Viewers.queue`; inside that one coordinated read the file's identity (`fileID`) and stamp are read before the bytes and again after them (and again after a Quick Look export, which reads the file itself), and a load is used only when both agree, else read again, three times at most, then failed (`ViewerLoader.read`, "kept changing"), so pages are never paired with another file's identity; one load at a time per viewer (`ViewerLoads`, Phase 1's `NoteShelf.ScanGate`, the one lifecycle the document, each set of versions, each version's picture and the thumbnails share): a load is one unit (`ViewerLoadUnit`) from the read through export, WebKit's conversion and parsing to the accepted result, its gate held all that time and released exactly once whatever ends it (a `finish` that runs once, and on the unit being let go of), and what it learns (identity, bookmark and stamp; a copy's `seen` state and pages; a picture) committed only through `accept`, when it's still the newest and its owner open, so a conversion cut short leaves that copy to be read again; drawing is a unit of its own (thumbnail passes; each version's picture, coalesced per version, so paging quickly draws a follow-up, not every page); changes while one runs make exactly one follow-up, which reads the file as it is then, and superseded or closed work stops at its next step (`ViewerLoadToken`, a thread-safe generation and closed flag checked before each try, before a Quick Look export, at each step of WebKit's conversion (`ViewerWeb`'s `current`) and between thumbnail pages); the file is watched before its first read, the read starting only once the watch is armed (`ViewerWatch.whenArmed`, after its sources are resumed; `Viewers.queue` is concurrent, so order there proves nothing), so a change while it loads always starts a reload; binding the PDF view to a new document takes the page to show first and ignores PDFKit's own page changes while it rebinds (`ViewerModel.rebinding`), so a reload keeps the page shown, or the one asked for during it; every original is read one way, on every try (never only the first): `ViewerLoader.readPinned`, the path rule and its identity right before, through a descriptor opened with `O_NOFOLLOW` (the document's load, the versions' source and the PDF comments' reads alike), so a file that becomes a link to somewhere outside between two tries is refused; anything else goes through Quick Look's own export, and Quick Look is never given the original's path: it previews Petal's private copy of the checked bytes (`ViewerQuickLook.export(bytes:name:unit:)`, `ViewerLive`; `qlmanage -p -o` into a folder of its own under `Config.supportFolder`'s `Viewer`, owned by a `ViewerExport` that removes it once nothing holds it, used or dropped by a newer load or the viewer closing; the dock's launch sweeps away exports older than ten minutes), and Quick Look's own view shows that copy too (`ViewerModel.liveURL`): a PDF it gives (iWork) is the pages; its HTML preview (Office) is laid out by WebKit in its own process (`ViewerWeb`: a content rule list installed before anything loads blocks every load but `file:` and `data:`, and no rule list means no load; page scripts off), drawn once as one long PDF and cut off the main thread into a page per slide (`div.slide`) or per page height at the ends of blocks (`ViewerPages.cut`), so its words stay text; nothing exported (Numbers), Quick Look's own `QLPreviewView` shows it and notes go on the file.

### Following the file

The file and its folder are watched (`ViewerWatch`, its descriptors opened off the main thread; a burst is one change): a change is read again, the file shown found again by its own incarnation first (renamed or moved, whatever file took its old path; `ViewerModel.follow`), that incarnation gone (a save made a new one) the file now at its path, nothing there the file its bookmark finds (made with every read, so the first move is followed, and a replaced file's bookmark is its own).

### Passages are found by their words

**Passages are found by their words, never their coordinates** (`ViewerPassages.find`, Phase 1's whole-quote rule, `NoteMatch.pick`): each margin note's quote is found again in the pages shown, with the words before and after it, off the main thread whenever the pages or the notes' passages change (`ViewerModel.resolvePassages`); not there, or two places as likely, it's "passage moved": on the file, no highlight, and no positioned comment. A note's saved `bounds` only say where it was.

### One file resolver

**One file resolver** (`ViewerFiles.locate`, for the margin, the PDF comments, the tools and "Open in Petal's viewer" alike, off the main thread): each place that names a file (a `file` place, or Phase 1's sentence in a file: a `passage` with a path or bookmark and no page address) resolves on its own: the very file it was made on (its `fileID`, an incarnation: "mac|volume UUID|inode|creation date in ms"; a volume with no UUID, some network shares and older drives, stands in as "local-<device>-<mount path>", known only on the Mac that recorded it, looked up only while that device is still mounted there, and never trusted by another Mac, where the bookmark and path decide; looked up only on that Mac, on the volume with that UUID with `fsgetpath`, and taken only when all of them match, so a reused inode is never it), else, that file not found as that incarnation (a save that made a new one, another Mac's record), the file its bookmark finds, else, with no bookmark, the file at its path; a place whose bookmark (made on this Mac) finds nothing opens and matches nothing, while another Mac's record or bookmark says nothing here, so its path decides (Phase 1's rule); which Mac a place was made on is its file's record, else (a place Phase 1 made) the `mac` it records (`ViewerFiles.isForeign`).

The desk uses it too: each read of what's in front works out, off the main thread, which notes' file places and sentences-in-a-file are that very file (`NoteScene.onFile`, by `NoteStick.fileKey`; `NoteMatch.onFrontFile`), so a path another file took never shows them and a renamed file does; a place made from that very read carries its record and fits at once; Phase 1's path rule only when it couldn't be worked out. `followFiles` follows bookmarks whenever no note here is on the file by its identity, even when a path matched. Two file places (or sentences in a file) are the same place only as the same passage (`samePassage`: its words and the words before and after them, so the same words twice on a page are two places) on the same file (`NoteStick.sameFile`: the same recorded `fileID`, else, with neither recorded, the very same bookmark at the same path) at the same position; a path alone never proves it, and what can't be proven the same is kept, never merged or replaced (`samePlace`, the one equality every dedupe and replacement uses).

The viewer's membership (`ViewerModel.refreshPlaces`) is worked out for its load's checked identity, each read a turn of that load: only the newest turn lands, and one from a load since replaced runs again. The scene records the places its membership was worked out for (`NoteScene.resolved`); a note's file place it never saw (synced from another Mac, an older bookmark, a place changed) makes it stale (`resolves`), and `refresh` reads what's in front again through the same gate as every look. A shared path never names two files: a new file that took the path while the place's own file still exists is never it, and a bookmark that finds nothing is never replaced by the path alone (bookmarks fall back to their path, so the identity comes first). Phase 1's reads and the viewer write `fileID` on every file and sentence-in-a-file place they make; a place made before (or with the older "device:inode") goes by its bookmark.

### The margin

**The margin** (`ViewerMarginView`), read only while the notes' folder is switched (`Viewers.folderSwitching`, called by the desk before its store stops taking changes: every margin's editor saved and closed first; `marginEditable`), shown only while `notes` is on (`ViewerModel.marginOn`; turning notes off saves and closes the paper open there, hides the margin, its highlights, New note and Note, and turning them on shows it again): every paper of the notes with a place the resolver says is this file (`ViewerModel.onFile`, `ViewerMatch.place`: a passage, then a page or slide, then the file), one of a conflict's papers too, read only with Keep this one as on the desk, each by its paper key (`Viewers.rekeyed` follows a rename); lined up with their passage's highlight or their page's top (`ViewerMargin.layout`, pushed down, never overlapping), the rest folded below as a cascade, those on other pages first, then those on the whole file or whose passage moved; an open paper is never in the cascade's right column but at the margin's full width on a row of its own (`ViewerMargin.cascade`).

The margin scrolls in step with the pages (`docScroll`: either scrolled moves the other, as far as the pages go), so notes past the end are reached and lined-up ones stay lined up; with one slide at a time it scrolls on its own. The sketch's dashed line runs from each found passage's highlight (24% of its notebook's color) to its paper (`ViewerInk`, from the same layout). A passage is marked line by line (`ViewerModel.lines`: PDFKit's `selectionsByLine`, one rectangle per line, in the viewer and as one quadrilateral per line in the comments written, `ViewerComments.quads`), never one box over the words either side; the lines' union only says where its note lines up. PDFKit's view tells the model the page shown, the selection, where each passage and page is, and how far the pages have scrolled (`ViewerPDF.Coordinator`, converting the page's points to the window's); a selection's page text is never extracted on the main thread, nor its own string read there: the page's text, the selected words and whether there are any come from a copy of the document of its own per load (`ViewerText.read`; `macos/checks/run.sh` fails on a selection's string read in `ViewerViews.swift`), and only the latest selection's answer, for the pages still shown, is kept (`ViewerTurns`); a new selection starting clears the one before (and its Note) at once. Quick Look's own view follows the file to its new path before it's refreshed.

### Margin papers

Margin papers are the notes themselves (`PaperView` at 310 points, with the desk's editor and `write`, so every change goes through the note's session), each view known by its note's identity (`ViewerPaperID`: an editable paper by its holder key, so a rename keeps the same editor and its typing; each read-only copy by its file), and an editor's save goes to the note as it is now (`NoteShelf.saveTarget`: its file only while the paper there is that note by holder key, else the one paper of that note's id, followed through an id given meanwhile; never a guess and never the key alone: unresolved, the typing is journaled under the note it was typed in); the corner of a paper turns that paper over (opened or handed over first); the paper open in a margin whose window is on screen counts as showing its pictures (`Viewers.picturesShown`, in the desk's `picturesOnScreen`; the window's occlusion, the open paper and its face changing tell NotePictures); one opens at a time, and a note open in the viewer is open nowhere else: `NoteDesk.heldByViewer` (by the note's identity, its holder key, moved by Phase 1's identity change when an id-less note gets its own id: `identityChanged`) hands it over from the viewer before the desk opens or turns it (`releaseFromViewer`), and the viewer opening one the desk has open hands it over the other way (`NoteDesk.handOff`): a transfer saves what's typed and is never a fold, so an empty note just made is never let go of on the way (`ViewerClose`), and the viewer folds the desk's paper before it opens one. Petal's viewer coming to the front hides the notes on the window left behind (`viewerFront`, as any app coming forward).

### The viewer as the desk's current place

While a viewer's window has the keyboard it's the desk's current place (`Viewers.front`, by `keyID`): "here" for the note tools counts its margin notes (`NoteDesk.hereNow`), sticking "here" (`stickHere`) takes its file (`ViewerModel.fileAnchor`: the `fileID` and bookmark its latest read made; only from a finished load, its checked identity, pages and page shown all its own, waited for while it loads (`whenIdentified`) and nothing offered without it, so no file place from the viewer is ever saved by path alone; a reload, the file changed or followed, is a load like the first: loading again, with no identity, bookmark or selection kept from the load before, the pages shown kept on screen meanwhile and text selected on them during it never offered, so a note asked for during the reload of a replaced file gets the new file's identity or none), its page or slide, and its selection as a passage, checked against the vault over the page's whole text as `Assist.selectionInSecret` checks a field's (`ViewerModel.herePlace`, the same path as New note; never a window, tab or app of Petal's own), ⌃⌥N makes a note there, open in its margin, and a margin paper's letterhead offers its file and page to stick to (`NoteDesk.stickOffers`, `shownIndex`: the one current place, never the last scene outside the viewer).

A selection still being read is waited for, never taken for none (`selectionPending`, `whenSelectionSettled`), and a place is used only while the viewer is open with the document and selection it was made for (`hereContext`: its load and selection turn), else nothing is made. An editor's registration is cleared only by that editor going away (`editorRegistered(_:_:token:)`), so a note closing on the desk as it opens here never loses the new one.

### A new note

**A new note** (New note, or Note by a selection) is a `file` place with `page` or `slide` (from 1), and for a PDF selection the passage fields (`quote`, `before`, `after`) and `bounds` ("x y width height", the page's points from its bottom-left corner; numbers a page can't have, past a million points, are no bounds and are kept as written): exact here, and the same note shows on the file in Preview or Acrobat (AXDocument). refused, changed or unreadable, nothing is made or copied); picks are offered and settle only while the viewer's loaded document is that base, unchanged (`pickSuspended`, `ViewerVersionSet.pickState`): changed, replaced, deleted, refused or being read again, Use this is held back, the strip says why ("The original changed — make versions again"), `whenPicked` and `petal_view_pick` answer with it, and the copies stay; ### Notes as comments

**Notes as comments** (`ViewerPDFComments`, `petal_note_pdf_comments`): each note on a PDF as a highlight where its passage is found now (by its words in that PDF) or a sticky note on its page (the first for one on the whole file, whose passage moved, or whose page is gone), every sticky note placed and kept inside the page's crop box (its whole rectangle, whatever its origin) at the corner that shows at the top left once the page is turned (`ViewerComments.spot`, `topLeft`, `inside`), its whole text redacted with the vault's index before it's made plain or cut (unreadable: nothing written); written in a folder of Petal's own on the PDF's volume, then into "Name (with notes).pdf" beside it, or into the PDF itself only when asked and allowed (`Assist.ask`, every time), the original kept beside it as "Name (before notes).pdf" first. ### The reading lens

**The reading lens**: a margin note's right-click menu has "Follow what I select" (`follow`; its footer then says "Follows what you select"). It is off until the person turns it on for a note, is never saved, and goes off when the viewer closes (`close` calls `follow(nil)`). With it on, each selection that settles in a paragraph (0.6 seconds after the last one: nothing is asked while it's still moving, `lensSoon`) makes a `ViewerLensRequest` (its page, paragraph and selection, cut from the page's text after all of it was checked, secrets shown as (hidden); unreadable, nothing is asked) and asks the note's helper (`askLens`, `NoteHelpers.lens`; `onLens`, when it's set, is asked instead: `Petal --viewer-check`). The note's own words are the instruction: the quick AI (Brain: Haiku at low effort, or Codex's quick setting) is asked to do what the note says to those words, with their paragraph for context, and a note with no words means "explain this in plain words" (`NoteHelp.lensAsk`, made only from `Shielded` parts). One call at a time per note: a newer selection ends the one before (`lensOff`, `lenses`), so only the newest answers. Its answer is shielded whole as it arrives and shown short (`ViewerLens.short`) in Petal's ink beside that paragraph in the margin (`answerLens`), a faint "…" there until it's in; when there's none, why, faintly (the AI not set up, notes getting ready, the vault unreadable).

### The viewer's tools

The viewer's tools answer through the vault's redaction (`Viewers.shielded`, `NoteShield`): file names, labels, copies' names and paths; nothing is told while the vault can't be read. The notes they count or hand on are sources like any other: an agent is told of, and `petal_note_pdf_comments` writes for it, only the notes it may read (`Viewers.readable`: a Private notebook's only for a helper of a note inside it, the note tools' rule; the person's own button writes them all), and a note's helper is answered only through its admission gate (`Assist.handle`, `NoteHelpers.admitTool`: before the tool, and again right before its answer). They name the file the agent gave by its name (redacted), never its resolved path, and give paths only for the copies the agent edits. `petal_view` also tells the words of the page or slide it shows (`text`): read off the main thread from that load's own copy of the document (`ViewerText`), told only for the page still shown of that load, redacted whole with the rest of the answer and cut to `Viewers.textLimit` only after (`fitText`).

## Speed with many notes (phase 5)

What was slow with 500 notes in 20 notebooks, and the rule that replaced it. `macos/bench/notes-before-after.txt` has the numbers.

### One read of the folder at a time

`NoteStore.reload` reads the whole folder off the main thread, one read at a time (`RootSession.reading`): asked for while one is under way, exactly one more follows it, begun after the ask (`readAgain`, `beginRead`). A read is never thrown away for a newer one, so under a steady stream of changes (iCloud bringing a folder down, many pictures pasted) every read that runs lands, and a save never waits on the files' queue behind reads nobody will use. `reload(then:)` calls back once a read begun after the ask was taken in (the checks and the bench wait on it). `NoteStore.working` says whether anything of the folder's is under way (its entering, a read, a note's work, a cover or a canvas being written).

### A file is read once while it doesn't change

`NoteStore.read(_:cache:)` keeps what the folder's last read made of each note file (`ReadCache`, one per `RootSession`, only ever touched on the files' queue). An entry stands only for the very file it was read from, unchanged: the same volume and inode, the same length, and the same times its words and its inode last changed (`ReadCache.Stamp`; the second moves on every write, rename or change and can't be set back). It's kept only when the file was the same before and after it was read. So a read after one note changed costs a listing and that one file; bookmarks are still followed and iCloud's versions still read every time.

### Finding a paper, and the Private notebooks

A paper keeps its key (`PaperNote.key`, set with its URL and version, never worked out from the URL each time it's asked). `NoteStore.paper(_:)` finds a paper through an index of the notes as they are (`RootSession.byKey`, made again only after `notes` changed). `NoteStore.privateBooks` is worked out once for the notes and notebooks as they are (`RootSession.privateBooks`), each notebook held notes are in weighed once (`NotePrivacy.privateBooks`): it's asked for every note a tool weighs. A search's tickets are made together (`NoteDesk.tickets`), and a ticket whose paper is still at its file is followed through the index (`repick`, with the answer `NoteShelf.pick`'s first rule gives). `NoteStore.places` finds the covers once, then each notebook's own.

### The Petal Notes window

The window keeps an index of the notes while they don't change (`NotesModel.index`, by the store's session and `notesVersion`): the papers, and what the search looks through folded once, as bytes (`NoteLibrary.searched`, `NoteText.Folded`; a word is looked for with one pass over memory, `NoteText.matches(words:folded:)`). A note's title and preview are kept by the words they were made from (`NoteText.derived`, an `NSCache`), so a body is read into lines once, not once per paper drawn. The sidebar's rows (`NotebookRow`) and the grid's papers (`GridPaper`) are `Equatable` views: drawn again only when what they show changed. A search, a notebook and a view across notebooks are one page (`NotesWindowView.main`, `shown`), put back at its top when it shows other notes. The grid (`NotesGrid`) is as tall as all its rows, but makes only the rows in or near what its scroll view shows (`sight`, from `GeometryProxy.bounds(of: .scrollView)`), the same number wherever it's scrolled to, and reuses their views as it scrolls and as the notes found change (`reuse`: one view per place among the rows made, as a table reuses its cells). Its papers are placed by a layout of its own (`GridSlots`) that never measures them and has no alignment guides. A paper's words in the grid are no more than it can show (`GridPaper.shownWords`, `shownLines`).

### What Petal AI did

Every line of "What Petal AI did" goes through one function, `Assist.did`, which takes a `HistoryLine` and nothing else. A line's own words are Petal's, written as a literal; whatever it names (an app, a window's title, a file, a site, a memory's words, a vault item's title, what an agent said it was doing) can only go in as a name (`\(named:else:)`, `\(quoted:else:)`). Each name is put through the vault's settled redaction off the main thread before the line is kept, and left out while the vault can't be read; a line is kept by when it happened. A raw string is not a line (`macos/checks/run.sh` compiles snippets that must fail).

### The bench

`Petal --bench-notes [--json file]` (`NotesBench.swift`) makes 500 made-up notes in 20 notebooks in a throwaway folder of its own (its settings, state and notes are folders beside it whatever the environment says; a made-up vault; nothing shown) and times the real store, Petal Notes window, note tools, desk layout and editor: the first read until notes are ready, a read after one file changed, the window opening, switching notebooks and to a canvas of 100 notes, a search typed a character at a time (the person's own, and the tools' redacted one), the grid scrolled, the tabs on a window with 30 notes, a note with 20 pictures, and idle CPU. Beside each time is the longest the main thread was held (a wait on the disk would show there). A headless run never orders a note's panel in (`NSPanel.unveil`), so it runs the desk's own `layout`. Not met: a keystroke that changes which notes are found takes 22 to 38 ms (the target was 16.7 ms at p95), because the papers in sight are set in type again by Core Text.

## Checking it

What runs real code, and what only reads the source:

- **`macos/checks/run.sh`** compiles the pure files with a check each and runs them (file formats, layout, the store's file work on throwaway folders through the real `NoteStore`, `NoteJournal` and their queues), compiles snippets that must fail (the `Shielded` boundary, `HistoryLine`), and reads the source for the shape of rules that can't be run without the app (one `start`, one `end`, one gate, one `did`). The source reads keep a rule from being bypassed quietly; they don't show that it works. Run it after any change to notes.
- **`Petal --helpers-check [--ai]`** runs the app's real code end to end, headless, with a stand-in AI (below).
- **`Petal --viewer-check [<file>…]`** loads documents as the viewer does and drives the real viewer, tools and desk headless. Given no file it makes its own in a throwaway folder (`ViewerSamples`: a two-page PDF with the words its steps look for, a Word document through AppKit's writer, a three-slide deck zipped there), and it points Petal's settings, state and notes at folders of its own unless the run says otherwise.
- **`Petal --snapshot <folder>`** draws every view from made-up notes; native controls, scroll views and glass draw as placeholders there. `dock-note-pad` is the pad with a paper coming off it, `note-on-screen` a note kept on the screen over a made-up window.
- **Only on a real screen:** dragging a paper (that it follows the pointer and stays where it's let go), the open hand over it, and a drop from the note pad or the AI button onto a window, a Desktop or (with Option) the screen. The pure side of each is checked (`NoteLayoutCheck`: a paper left anywhere, on any screen, is exactly there again, folded, opened and after its window moved; `NotesCheck`: the screen place's round trip, rank, one Mac only, its placement, "Keep it on screen"), and what a click reaches on a real paper's panel (blank paper, the strip and the letterhead's row reach `PaperGrab`; the letterhead's buttons, the folded corner and the editor keep theirs) was looked at once off screen when it was built; the rest is the mouse's.
- **`Petal --bench-notes`** times the real code (above).

A check never waits a length of time and then looks: each wait is for the thing itself (the store ready, a read begun after the ask taken in, nothing under way, a file there), with a long limit only so a real failure ends the run. `NoteStoreCheck` has `wait`, `turn`, `idle`, `readAgain` and `reading`; the viewer check's `wait` lasts as long as it needs and says so when what it waited for never came, and its `pause` is only for showing that something does not happen. A step that follows a new note finds it by its id (its key changes when its file lands under its own name).

### A helper's own display

With `runDisplays` on (the default), a helper's windows open on a hidden display of its own (`RunDisplay.swift`, its pure rules in `RunDisplayPlan.swift`). What a helper's run has to do with it:

- **One display per note.** `NoteHelpers.begin` joins the run to its note's group (`RunDisplayRules.group`: `note-<id>`, under the name `NoteHelpers.displayRun(token)`), which makes nothing; the display is made the first time one of the note's runs opens something with `petal_apps` (`RunDisplays.need`). A second opinion is a new run on the same note, so it shares the display: `release` lets the ended run go one turn of the main queue later (`leaveDisplay(after: true)`), after `handOn` has begun the reviewer's run, which has joined by then.
- **Every ending lets go.** `release` (every end: done, failed, stopped, the note gone) and `pause` and `park` (Pause takes the display away; Go on gets one again at the next open) call `leaveDisplay`; with the note's last run the display is removed. As a net, `RunDisplays` asks each run once a second whether it still goes (a helper's: its token is running) and lets it go after two misses.
- **What's left on the display** is settled before it's removed (`RunDisplays.settle`, off the main thread). First the apps the run itself started (`RunDisplays.Launched`: the app wasn't running before the run's open; `RunDisplayRules.leftover(app:)`): one the person didn't use since, with no window of it brought to their screen and no window that says it has unsaved changes, is asked to quit politely (`terminate()`, never forced) and given `RunDisplayRules.quitBound`; one that can't be read, or doesn't go in time, is kept. An app the person already had open is never quit. Then each window (`RunDisplayRules.leftover`, `holdsNothing`): one the run opened bare (an app with no file and no address), did nothing in, and that reads as holding no document and no unsaved change is closed, and so is a dialog with no document behind it (an Open panel, a welcome window); everything else is moved to the person's main screen, behind what they're doing, never raised. A window the person took with Show me is left where it is, and nothing of an app that became theirs is closed. Petal quitting does the same in one pass (`RunDisplays.quit`): it asks and doesn't wait.
- **Whether the person used an app** the run started (`RunDisplayRules.personUsed`, `RunDisplays.cameForward`, `sampleFront`): it came to the front within a moment of their last key, click or scroll (Petal never brings a run's app forward itself), or they pressed a key or clicked while it was in front; Show me and `petal_windows` show count too. It's theirs from then on.
- **Waiting its turn** ("Waiting for a display") shows as the run's line in the AI button's preview (`NoteStatus.Facts.waitingForDisplay`) and on the helper's bar (`HelperBar.line`); the tool call that needs the display waits with it (the socket's heartbeat keeps it alive, as for a card).
- **Two runs, one app** (`AppTurns`, `RunDisplays.turn`): a helper whose open (`Assist.openOnDisplay`) or act (`ComputerUse.proceed`) is in an app another run is using on its display waits in order, its line and its bar saying "Waiting for TextEdit" (`NoteStatus.Facts.waitingForApp`, `RunDisplays.waitsForApp`), and goes ahead when the other ends or lets the app go (its windows of it closed or shown to the person). Its tool call waits with it; a run that ends while it waits is told. The same line shows while a helper waits for the person to leave an app it needs real keys in (`Background.personFirst`, up to `personPatience`; the act line moves on meanwhile). A run never sees or acts in another run's window (`RunDisplays.foreign`, by where it is and by its number).
- **Its acts there** go the background way always (`ComputerUse.Map.hidden`, `Background.Situation.hidden`): no pointer, nothing forward, and what the background can't do says Show me instead of "bring it forward" (`Background.Reason.words(_:hidden:)`). The helper's bar has Show me while its run has a display.
- **Its system prompt** says so only while `runDisplays` is on (`NoteHelp.ownDisplay`, Petal's own words, `Shielded`).

### `Petal --helpers-check`

**Helpers in notes, end to end:** `Petal --helpers-check [--ai]` runs helpers for real without showing anything (`HelpersCheck.swift`): headless, on throwaway folders it makes itself in the temporary folder (`PETAL_CONFIG_DIR`, `PETAL_SUPPORT_DIR`, `PETAL_NOTES`; it runs nothing if Petal's folders were read before it could point them there), a made-up vault, no socket, never the Keychain. It builds the real `PetalApp` (the store, the desk entered through `NoteDesk.startHeadless`, the helpers, `Agent`, `Brain`), gives each note its real editor (`NoteEditorView` in a window that's never ordered in), types a line into it and presses Return (the editor's own `insertNewline`, which hands the line to `returned`). The AI app is a stand-in the check writes there (`PetalApp.standIn`): a script that speaks Claude Code's stream-json for a chat turn and its one JSON result for a quick call, and plays a fixed transcript per call; everything on Petal's side of that process is the real path.

### A note's editor never drops a refused save

**A note's editor never drops a refused save:** when `write` can't land (the notes' folder switching, a drain, the paper gone) the typing goes into the journal at once as a whole snapshot under its note's id: the whole note as a normal save writes it, its front matter and the edited body, with the pictures and the pastes still being read for it, as the ordinary snapshot carries them (`NoteShelf.unsavedText`, `NoteStore.unsavedEntry`; an id-less note's text is its body, as its file is), made on what the editor had (`NoteStore.journalUnsaved`; put back by the next launch's recovery, into that note while it says that, else beside it); undone back to what's saved, that snapshot is retired, or replaced by the note as it is when writing still waits, keeping any picture or paste recovery still pending (`settled`, `NoteStore.settleUnsaved`, `NoteJournal.retire`), and the editor stays dirty (`EditorMarker.saved(landed:)`), keeps its text as unsaved, takes no newer version meanwhile, and tries again until it lands. An editor still dirty with no save waiting (between tries) hands its text over when it's flushed (closing, quitting: `flush` runs a save then too); a read-only paper's typing kept beside it counts as handled.
