Your own agents

Petal connects to your own Claude Code and Codex so they can read and change the dock, work with Petal Notes and run commands with vault API keys they never see.

Connecting Claude Code and Codex

Turn on Settings › Petal AI › “Let other AI agents change Petal” (on by default). Petal registers its tools with Claude Code (claude mcp add -s user petal …) and Codex (codex mcp add petal …), installs its skill for each and links the petal command at ~/.local/bin/petal.

Turning the switch off removes all of it. While it is on, Petal's tools are available anywhere that runs your Claude Code or Codex, such as a terminal or T3 Code.

What agents can and cannot change

Connected agents can read and change settings and the dock, read and write Petal Notes, and use Petal AI's tools.

They can never widen Petal AI's access, turn on “Let Petal AI use your apps”, or remove apps from “Kept private”. Those stay in Petal's own settings.

Vault keys for agents

When an agent runs a command that needs an API key from the vault, the first use in a project shows a card naming who is asking, what key it wants, the command and the folder — for example: “Codex in T3 Code wants your Anthropic key for “npm test” in ~/petal”.

Choose one of three buttons:

  • “Allow once” for that single run.
  • “Always for this project”, available only for your own signed Claude Code or Codex, and never for your home folder.
  • “Don't” to refuse.

Manage saved grants in Settings › Vault › “Other AI agents”, where you can “Remove” any grant or choose “Allow an agent” to add one ahead of time.

Keep in mind. Agents ask first unless allowed in Settings › Vault › “Other AI agents”. They never see a password or key directly, though a command written to print one can still reveal it.

Passing a key in Terminal

For engineers. Use petal run to give a command a key from the vault without putting it on the command line:

petal run --key "<title>" [--env NAME] [--stdin] -- <command…>

Petal puts the key into the matching environment variable (ANTHROPIC_API_KEY, OPENAI_API_KEY, GEMINI_API_KEY, XAI_API_KEY, GITHUB_TOKEN or STRIPE_SECRET_KEY, or the name you pass with --env), or pipes it on standard input with --stdin. Any occurrence of the key in what the command prints is replaced with [<title> key].

Keys shorter than 16 characters are refused. Never pass a key as a command-line argument.
